# Dreamsleeve Client UI

React/TypeScript-интерфейс с общей игровой точкой входа и отдельным браузерным
стендом. Native host bridge реализован в SKSE DLL (`src/Dreamsleeve.Client/UI/PrismaUI.ixx`,
[описание](../../docs/SkseClientRu.md)); браузерный стенд проверяет UI, но не заменяет проверку в Skyrim.

## Запуск

Node.js 22.12+ (проверено на 24.12). Из этого каталога:

```powershell
npm ci
npm run dev
# http://127.0.0.1:5173/demo.html
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

Если Chromium недоступен, можно использовать установленный Edge:
`$env:UI_BROWSER_CHANNEL='msedge'; npm run test:browser`.
Browser tests сохраняют скриншоты в `test-results/`.

`npm run build` проверяет TypeScript и создаёт `dist/` для игры: прозрачный фон,
UI, PrismaUI bridge и `theme.user.css`. Проверка артефакта отклоняет попадание
dev-данных, localStorage и стенда. `npm run build:demo` отдельно создаёт `dist-demo/`.
Игра не требует Node.js, Vite server или доступа к CDN. Загружать нужно `index.html`
из всей папки `dist`, сохраняя относительное расположение assets.

## Что работает

- Пассивный чат, ввод, закрытие, fade, время сообщений и цвет каналов.
- Общая вкладка и фильтры каналов, отдельный канал отправки и unread-счётчики.
- Системный канал объявлений только для чтения; у серверных объявлений нет автора, у клиентских — игрок, чей клиент их отправил.
- Начальный снимок и добавление сообщений, история до 500 строк на каждый канал (занятый канал не вытесняет другие), дедупликация по паре «канал + id».
- Собственная отправка сразу видна затемнённой UI-строкой; серверная публикация заменяет её. Отказ оставляет текст с кнопкой повтора.
- Просмотр истории не сбрасывается новыми сообщениями; переход к непрочитанным.
- Онлайн, профиль, базовая статистика текущего представления.
- Fade, масштаб, шрифт, межстрочный интервал, фон, тема, временные метки и формат имени.
- Закрепление, перетаскивание за заголовок, resize за угол и ограничение окном экрана.
- Метки на земле: кнопка «Оставить здесь» рядом с «Отправить» (черновик уходит меткой, не в чат;
  строка ожидания «[Метка] Вы: …» с «Не оставлено: …» и повтором), панель «Метки» с полным
  списком своих меток (удаление) и списком меток рядом с подробностями, блок настроек «Метки
  на земле» (с игровой датой: календарь «Тамриэльский»/«Привычный», дата над местом смерти и
  над надписью, цвет даты); стиль облачков дополнен рамкой и цветом
  текста (`#RRGGBB`). Подробнее: [SkseClientRu.md](../../docs/SkseClientRu.md#метки-на-земле).

На стенде Enter или кнопка открывает чат; новая публикация не захватывает фокус.
Группа/гильдия/личные сообщения на стенде — демонстрационные каналы, не новые
возможности сервера. Кнопка «Отклонить следующую отправку» проверяет ошибку в строке
и ручной повтор. Настройки стенда сохраняются локально в браузере. В игре сохранение
передаётся native host и должно идти в TOML по выбранному конечным клиентом пути.
UI не сообщает об успешном сохранении до ответа host.

## Bridge v1

Типы: [bridge/types.ts](src/bridge/types.ts). UI-модели не являются protobuf-схемой.
Идентификаторы передаются строками, включая uint64. JSON — формат внутрипроцессного
bridge, не формат конфигурационного файла. Код приёма регистрируется до React mount.

Native host создаёт view, регистрирует JS listener `dreamsleeveCommand`, затем
передаёт снимок через `InteropCall(view, "dreamsleeveReceive", json)`.
Если listener отсутствует, команда не теряется молча: UI сохраняет текст в строке с ошибкой и
показывает ошибку. Вызовы из callback нужно маршалить на основной поток владельца
ClientApplication. Не вызывать его методы непосредственно с неизвестного потока.

| Host → UI | Смысл |
|---|---|
| `snapshot` | Каналы, последние сообщения, онлайн, selfId, serverName и необязательные settings |
| `messages` | Новые авторитетные публикации; пакет максимум 500 сообщений |
| `players` | Текущий список метаданных онлайна; без потока координат |
| `activate` / `deactivate` | Native focus получен / освобождён |
| `connection` | Изменение состояния соединения |
| `sendResult` | requestId + messageId при успехе либо requestId + error при отказе; это не публикация |
| `settingsResult` | Подтверждение записи настроек с revision или ошибка |
| `announcementResult` | channelId, source, text, error: объявление другого мода через API не опубликовано; для неизвестного канала не показывается |
| `settings` | Сохранённые настройки из `ui.toml` сразу после готовности страницы, до снимка и без соединения |
| `ignored` | Личный список игнора текущего сервера: id и имя, уже разрешённое host под текущие настройки |
| `auth` | Типизированное состояние входа: authenticating, operation, failure, error, savedLogin, savedUsername, phase. Без пароля и токена. Приходит при любом изменении этих полей или фазы соединения и сразу после (пере)создания view |
| `groundMarks` | Полный список собственных меток с сервера (id, kind `note`/`death`, text, time, character, location `plugin:formid`, x/y/z, gameDate — игровая дата, уже отформатированная host в выбранном календаре, у старых меток отсутствует); в снимке — `groundMarks` и `groundMarksSupported` |
| `nearbyMarks` | Метки, которые сервер показывает рядом с персонажем, с именем автора (`author`) от host; в снимке — `nearbyMarks`; метки игнорируемых не приходят |
| `markResult` | Итог `placeGroundNote` (markId, evictedId) или `removeGroundMark` (removed) по requestId, либо error; это не дельта видимых меток |
| `displayName` | Смена своего отображаемого имени: pending (ждём сервер), changed (сохранённое имя, один раз), error (текст отказа); свой профиль приходит в `players` |
| `identity` | «Скрывать моё имя от других игроков»: mode (`off`/`everywhere`/`exceptGroundMarks`; во время ожидания — запрошенный), pending (ждём сервер), pseudonym (что видят другие, только в Ready-сессии), error (последний отказ); приходит при каждом изменении, после (пере)создания view и в ответ на `setIdentityVisibility` |

| UI → host | Смысл |
|---|---|
| `sendChat` | channelId, text, requestId корреляции UI |
| `close` | Освободить native focus; игру не ставить на паузу |
| `saveSettings` | Полный набор UI settings и монотонная revision |
| `signIn` | username, password, remember; непустой displayName — сначала регистрация, затем вход |
| `signInSaved` | Возобновить сессию токеном из диспетчера учётных данных Windows |
| `signOut` | Отозвать сохранённый токен на сервере, забыть его локально и отключиться |
| `forgetLogin` | Забыть сохранённый вход только локально; работает без сети |
| `disconnect` | Закрыть сессию, сохранённый вход оставить |
| `ignore` / `unignore` | playerId; host хранит список в `ui.toml` по адресу сервера и повторно проецирует снимок |
| `displaySettings` | nameMode, streamerMode и textFilter; host применяет и сохраняет сразу, затем шлёт refresh-снимок |
| `placeGroundNote` | requestId, text: оставить черновик меткой там, где стоит персонаж; положение подставляет host |
| `removeGroundMark` | requestId, markId: удалить свою метку |
| `changeDisplayName` | displayName: в Ready-сессии — запрос серверу; username не меняется; одна смена за раз |
| `setIdentityVisibility` | hiding (`off`/`everywhere`/`exceptGroundMarks`): в Ready-сессии — запрос серверу (выбор сохраняется после подтверждения), без сессии — выбор для следующего входа; пока сессия открывается — отказ «Дождитесь подключения к серверу» |

UI requestId относится к lifetime данного view. Host сопоставляет его с RequestId,
который создаёт клиентское приложение; не подставляет его прямо в wire-пакет.
Ответы обрабатываются асинхронно. При уничтожении view его callbacks и отображение
корреляций удаляются, чтобы старый ответ не попал в новый интерфейс. При reconnect
host выдаёт новый снимок. При разрыве pending сохраняется с пометкой «Доставка неизвестна»;
UI не повторяет отправку автоматически, поскольку публикация могла уже состояться.

Native host — источник полномочий: он допускает каналы и публикации, проверяет
команды и не позволяет клиенту создать системное объявление. UI также скрывает
read-only каналы из отправки, но это не серверная проверка прав. Объявления
приходят отдельным потоком (см. «Объявления» ниже); host должен объявлять
только реально поддержанные каналы. Некорректное событие bridge не применяется.
Текст сообщений выводится как текст, HTML не исполняется.

Настройки host валидирует и записывает атомарно через временный файл в TOML.
Не сохранять на каждом mousemove: UI посылает одну команду по окончании drag/resize.
Обычные настройки применяются сразу и записываются кнопкой «Сохранить настройки».
Ошибка записи оставляет настройки применёнными до закрытия, но явно отображается.
Пример TOML-секции — [ui.example.toml](ui.example.toml); native host читает и пишет её
как `ui.toml`. Блоки «Имена над светлячками» и «Сообщения над игроками» настраивают
нативный Scaleform-рендер SKSE DLL (`showFireflyNames`, `fireflyName*`, `showBubbles`,
`bubble*`): UI только хранит и передаёт их через `saveSettings`, сам ничего над
светлячками не рисует. Поля неизвестны старому host — он их игнорирует.

Каждый игрок и автор приходит с полем `name`, которое разрешает host (одно правило
для UI и нативных надписей): username, display name или имя персонажа из снимка
сообщения, с fallback на display name. В режиме стримера host присылает только
псевдоним (`alias`, `displayName`), `username` пуст, `character` отсутствует; UI до
прихода повторной проекции показывает заместитель «Псевдоним…» (`state/names.ts`).
Игрок, скрывший свои имена на сервере, приходит с `pseudonymous: true`: `name` и
`displayName` — серверный псевдоним, `username` пуст, `character` отсутствует (`parse.ts`
отвергает иное). UI помечает его знаком `~` перед именем через `data-pseudonymous` в
строке чата (с подсказкой «Имя скрыто игроком»), в списке и карточках онлайна и в
профиле, пишет «Имя скрыто игроком» вместо персонажа и «имя скрыто игроком» в
контекстном меню автора; `realNames` для него пуст, поиск идёт только по псевдониму и месту. Снимок с
`refresh: true` — та же сессия после смены имён или игнора: pending-строки, фильтр
и прокрутка сохраняются. Текст помеченных сервером сообщений host уже маскирует или
скрывает по `textFilter`; такие строки приходят с `filtered: true`. Правый клик по нику
открывает меню `views/AuthorMenu.tsx` (профиль, игнор). Подробнее: [модерация и имена](../../docs/ModerationAndNamesRu.md).

## Темы и layouts

`views/` содержит TSX-разметку, `features/` — поведение ввода/fade/геометрии,
`state/` — операции представления, `styles/` — структурный CSS, `themes/` — палитру.
Layout выбирается в `views/App.tsx`; `layouts/SkyrimLayout.tsx` можно заменить
другим компонентом с props `{ chat: Chat }`, переиспользовав hooks и отдельные views.
Не нужно изменять native bridge, state или модели сообщений.

CSS-тему можно установить без пересборки, изменив `dist/theme.user.css`:

```css
[data-part="chat"] {
  --accent: #aad0e0;
  --ink: #f4f4ef;
  --border: #6c929f;
  --surface: 12, 20, 26;
  --system: #f4d98c;
}
[data-part="message"][data-channel="guild"] { --channel-color: #a3d3a3; }
```

Публичные части: `chat`, `header`, `messages`, `message`. Атрибуты:
`data-channel`, `data-source`, `data-active`, `data-theme`, `data-full-color`,
у объявлений также `data-origin` и `data-kind`.
Все токены палитры перечислены в `themes/skyrim.css`; UI также передаёт
`--chat-font`, `--chat-font-size`, `--chat-line-height`, `--chat-background`.
Не привязывать пользовательский CSS к хешированным именам CSS Modules.
Собственные локальные шрифты подключаются через `@font-face` в файле темы;
следует предоставить кириллицу и учитывать лицензию выбранного шрифта.

CSS themes и замена layout при сборке — разные возможности. Универсального
исполнителя HTML-шаблонов и внешнего пользовательского JavaScript в игре нет.

## Следующая граница проверки

C++ host к ClientExchange, запись TOML и игровой ввод реализованы в SKSE DLL
([SkseClientRu.md](../../docs/SkseClientRu.md)). Реальные проверки внутри PrismaUI остаются
ручными: cursor, Enter/Escape, раскладки/IME, потеря фокуса, UI reload и стоимость CPU-отрисовки.
Прохождение Playwright в Edge не является подтверждением этих свойств.

## Большое меню и метаданные игроков

Кнопка ☰ в заголовке и счётчик онлайна открывают отдельное центрированное окно.
Онлайн, профиль, статистика, настройки и аккаунт переключаются внутри него. Окно не является
дочерним элементом перемещаемого чата: положение, resize и масштаб чата его не меняют.
Tab остаётся внутри открытого меню, Escape возвращает в чат. На узком экране
колонки перестраиваются, длинное содержимое прокручивается внутри окна.

Player в UI bridge теперь допускает zone, race, nearbyMarker/markerKind, interior,
activity/activityTarget, lockDifficulty, menu, gameStartedAt и actorValues.
ActorValue имеет key, name и value: число либо { current, maximum }. Все имеющиеся
показатели показываются в карточке; здоровье/магия/запас сил выделяются шкалами.
Отсутствие показателя не подменяется нулём, уровень 0 допустим. Значения не обрезаются,
только визуальное заполнение шкалы ограничено 0..100%. Координаты не требуются.
Это представление уже имеющейся телеметрии, не расширение серверного протокола.

connection может включать phase: disconnected/authenticating/connecting/opening/
connected/disconnecting/faulted. connected=true допустимо только для connected.
Подпись состояния читается непосредственно в чате; потеря соединения не скрывается fade.

На браузерном стенде кнопка сохранения записывает настройки в localStorage этого
origin, включая положение/размер после drag/resize. Перезагрузка страницы их восстанавливает.
В game build localStorage отсутствует; host обязан сохранить TOML и подтвердить запись.
Имя сервера пока не имитируется: получение и отображение добавим после web UI,
вместе с соответствующим контрактом native/server.

Онлайн имеет переключатель «Карточки / Список». Выбор сохраняется вместе с настройками
(`onlineView`) сразу после переключения. Список показывает игрока в одной компактной
строке: имя/персонажа, уровень, зону/локацию, занятие и HP/MP/SP. Полные метаданные и
прочие actor values доступны по нажатию на имя. Заголовки закреплены при прокрутке;
длинные значения сокращены с tooltip, на узком экране прокручивается только таблица.
Кнопка «48 игроков онлайн» на dev-стенде позволяет оценить плотность списка.

Пассивный режим использует отдельный fade для каждой полученной публикации.
Новая строка не возвращает яркость старой истории и не раскрывает фон/рамку чата.
Задержка отсчитывается от локального получения; повторная доставка не продлевает её.
История из начального снимка не вспыхивает как новые сообщения. Enter раскрывает
всю историю, Escape освобождает фокус и возвращает пассивный режим. Крестика скрытия
в чате нет; SKSE управляет полным скрытием через JS Hide/Show (см. ниже)
или видимостью самого PrismaUI view.
Кнопка закрытия большого меню лишь возвращает пользователя в чат.

В подключённом пассивном режиме заголовок, подсказка, фон, рамка и элементы управления
полностью невидимы: появление публикации показывает только её строку поверх игры.
Ошибка соединения остаётся отдельным видимым уведомлением.

## Аккаунт

Вкладка «Аккаунт» большого меню показывает фазу соединения, «Сохранённый вход:
<имя>» либо «Нет сохранённого входа», форму (имя пользователя, пароль, «Запомнить
меня», необязательное «Отображаемое имя (для регистрации)») и кнопки «Войти»,
«Зарегистрироваться и войти» (только с заполненным отображаемым именем), «Войти
сохранённой сессией» (при savedLogin), «Отключиться» (в подключённом состоянии),
«Выйти» и «Забыть сохранённый вход». Пока идёт операция, все кнопки отключены;
повторная команда не отправляется. Строка состояния переводит failure в текст
(«Неверное имя или пароль», «Имя занято», «Регистрация отключена», «Сервер занят,
повторите позже», «Сервер недоступен», «Некорректный ответ сервера», «Ошибка
хранилища учётных данных Windows», «Операция отменена», «Некорректный запрос») и
добавляет сырой error host, если он есть.

Пароль уходит в команде `signIn` один раз, не попадает в состояние zustand, лог и
localStorage ни в одной сборке; поле очищается сразу после отправки. Сохранённый
вход — это токен в диспетчере учётных данных Windows на стороне host; UI видит
только savedLogin/savedUsername. Меню ☰ и вкладка доступны до первого снимка и без
соединения: в этом случае ☰ открывает сразу «Аккаунт», в футере активного чата есть
кнопка «Аккаунт», а пассивный чат без сохранённого входа показывает короткую
подсказку под историей. Панели не открываются автоматически.

Если выбрано скрывать имя от других игроков, под сохранённым входом стоит та же
строка, что в настройках: «Другие видят вас как „Страж 2“», «Ожидание сервера…» или
«Имя будет скрыто при следующем входе на сервер»; отказ сервера — отдельной строкой.

## Режим стримера и скрытое имя

Блок настроек «Режим стримера» содержит две независимые настройки.
«Скрывать чужие имена (только у меня)» — флажок `streamerMode`, применяется командой
`displaySettings`, на сервер не уходит. «Скрывать моё имя от других игроков» — выбор
`hideIdentity`: «Нет», «Везде, включая метки на земле», «Везде, кроме меток на земле» (онлайн,
светлячок и чат всегда вместе). Он меняется только командой `setIdentityVisibility`: UI сразу
показывает «Ожидание сервера…» и выключает выбор до ответа, затем — «Другие видят вас как
„Страж 2“» (при «кроме меток» — «…; в метках на земле — ваше имя»); отказ («Сервер не разрешает
скрывать имя», «Слишком часто…») возвращает выбор и показывается под ним (`role="alert"`). Значение в `saveSettings` host
игнорирует: `ui.toml` получает его только после подтверждения сервера (`state/identity.ts`
строит строку состояния, `ChatState.identity` хранит последнее событие `identity`). Текст
под настройками объясняет, что сделанное под псевдонимом навсегда остаётся под ним, что ID
аккаунта виден всегда и что метки под настоящим именем выдают, кто стоит за псевдонимом.

Стенд имитирует сервер: ответ через 400 мс, псевдоним «Страж N» для каждого включения из «Нет»,
выбор хранится в localStorage `dreamsleeve.ui.hideIdentity`, кнопка «Сервер разрешает
скрытое имя: переключить» включает отказ; в фикстуре есть игрок «Страж 2» с
`pseudonymous: true` и его сообщение.

Стенд имитирует host: `signIn`/`signInSaved` дают `authenticating`, через 400 мс —
подключение и снимок; имя `bad` даёт invalidCredentials, `taken` с отображаемым
именем — usernameTaken. Кнопка «Сохранённый вход: есть/нет» переключает имитацию.

## Имя сервера и ожидание отправки

`[Server] ServerName = "Голоса Тамриэля"` в серверном TOML попадает в
`SessionOpened.server_name`, затем в `ClientOutput.status.serverName`. Host передаёт
его как `snapshot.serverName`: заголовки чата и большого меню используют это значение.
До welcome показывается Dreamsleeve. Пустое имя от старого сервера допустимо;
поле protobuf добавлено без смены версии wire-протокола.

Исход `MessagePublished` результата команды несёт messageId авторитетной собственной
публикации, результат — её generation и requestId. В одном Drain host сначала обрабатывает смену
сессии/снимок, затем подтверждения (с переводом native requestId в UI requestId),
затем дельты сообщений. Идентификаторы uint64 в JS передаются строками.
Снимок тоже может уже содержать подтверждённое сообщение; оба порядка поддержаны.
Отказы (`ServerRejection`, `CommandFailureCode`) преобразуются в `sendResult.error`.
Обрыв транспорта означает неизвестную доставку, а не подтверждённый отказ.

Pending — только представление UI, не запись в ClientModel или серверной истории.
Строка затемнена до совпадения messageId; совпадение текста не используется.
Через 15 секунд ожидания или при разрыве появляется «Доставка неизвестна»;
позднее подтверждение всё ещё обрабатывается. Автоматических повторов нет.
«Повторить» доступно только после явного отказа и создаёт новый requestId.
Неопределённую строку можно убрать; ручная повторная отправка может создать дубль.
Одновременно допускается одна ожидающая отправка, до 16 сохранённых проблемных строк.
При смене сервера/пользователя строки очищаются; при reconnect того же пользователя
сверяются известные messageId со снимком. При пересоздании view локальные статусы
не сохраняются. Pending не подсвечивает фон и рамку пассивного чата.

Нативный PrismaUI host пока не реализован: Core предоставляет данные и корреляцию,
веб-стенд демонстрирует bridge; реальное соединение UI с Core — задача SKSE-адаптера.

## Объявления

Системный канал приходит в снимке как канал вида `system` (только чтение) со своим
серверным id; UI находит его по виду, а не по id. Системное сообщение несёт `announcement`:
origin (`server`, `trustedClient`, `thirdParty`) назначает сервер, kind — `announcement`,
`event`, `admin` или `periodic`. `signature` другого мода — его собственная подпись
(до 128 символов, без управляющих), доверия она не повышает и выводится как текст.
`author` — игрок, чей клиент опубликовал объявление; у серверных автора нет.

Строка показывает вид («Объявление», «Событие», «Администрация», «Напоминание») и
источник: «Сервер», «Dreamsleeve · <автор>» или «<подпись> · <автор>». Автор
объявления — не кнопка: меню профиля и игнора у объявлений нет.

Блок настроек «Объявления» (`announcementChannels` = tab | all | current и
переключатели `announcementsServer`, `announcementsTrustedClient`,
`announcementsThirdParty`, `announcementsEvents`, `announcementsPeriodic`) — только
проекция UI, без запроса к host. `all` (по умолчанию) показывает объявления и во «Все»,
`current` — в любой выбранной вкладке. Выключенный источник или вид скрывается везде,
включая вкладку «Объявления», и не увеличивает счётчик непрочитанного.

`announcementResult` показывается в канале объявлений как отказ: «<source>: <text> ·
Не отправлено: <error>», с «×», но без «Повторить». Срок жизни как у прочих
отказов; такие строки первыми уступают место в лимите 16 и не блокируют свою отправку.
На стенде: «Объявление мода» и «Отказ объявления мода».

## Скрытие для меню Skyrim

После загрузки JS доступны `Hide()` и `Show()`:

```cpp
prisma->Invoke(view, "Hide()");
prisma->Invoke(view, "Show()");
```

Те же действия доступны через `dreamsleeveReceive` как `{ "type": "hide" }`
и `{ "type": "show" }`. Это отдельное transient-состояние, не настройка TOML.
Hide сразу убирает чат и большое окно, отменяет взаимодействие/перетаскивание,
сохраняет историю, настройки, черновики и pending. Данные продолжают приниматься;
snapshot, ошибка соединения и activate не отменяют скрытие. Повторные вызовы безопасны.
Show возвращает пассивный чат; для ввода нужен отдельный activate после получения
native focus. Возраст сообщений продолжает отсчитываться во время скрытия.

Если чат был активен, Hide отправляет команду close для освобождения native focus.
SKSE-адаптер должен также самостоятельно освободить фокус Prisma при входе в меню:
DOM-скрытие не управляет захватом клавиатуры движком. Hide действует и без listener.
Выбор разрешённых меню, включая loading, делает SKSE; UI не знает меню игры.
При перекрывающихся меню вычисляйте итоговую видимость по всему текущему набору,
как в примере TrueFlasksNG, а не вызывайте Show на каждое отдельное закрытие.
Первый Hide можно вызвать после готовности JS до передачи snapshot; при пересоздании
view адаптер заново передаёт текущую видимость. По умолчанию view видим.

### Совместимость клавиатуры и actor values

Обработчики Enter/Escape/Tab учитывают `keyCode`, если Ultralight не заполнил
`KeyboardEvent.key`. Отправка чата по Enter выполняется явно с отменой стандартного
submit, без повтора при удержании и без отправки во время IME-композиции.
Проверка с синтетическими событиями покрыта Playwright; поведение в Skyrim
необходимо подтвердить игровым тестом.

Native actor values используют ключи `skyrim:health`, `skyrim:magicka`,
`skyrim:stamina`. Карточки и компактный список сопоставляют их с цветами и
ресурсами через общий helper; demo использует такие же ключи.

Уведомление чата (например, «Настройки сохранены») затухает вместе с пассивным
HUD после Escape и не проявляется заново при новой публикации.

Закрытый чат без подключения полностью скрыт, включая статус, ожидание и подсказку входа.
Открытие чата показывает статус; Escape снова скрывает интерфейс. Подключённый
пассивный чат сохраняет показ новых сообщений и fade. В компактном онлайне
значения ресурсов отображаются шрифтом 13 px под подписями HP/MP/SP.
