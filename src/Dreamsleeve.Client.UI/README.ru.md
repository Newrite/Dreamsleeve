# Dreamsleeve Client UI

React/TypeScript-интерфейс с общей игровой точкой входа и отдельным браузерным
стендом. PrismaUI/SKSE DLL и native host этого bridge пока не подключены:
браузерный стенд проверяет UI, но не заменяет проверку в Skyrim.

## Запуск

Node.js 22.12+ (проверено на 24.12). Из этого каталога:

```powershell
npm ci
npm run dev
# http://127.0.0.1:5173/demo.html
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

Если Chromium недоступен, можно использовать установленный Edge:
`$env:UI_BROWSER_CHANNEL='msedge'; npm run test:browser`.
Browser tests сохраняют скриншоты в `test-results/`.

`npm run build` проверяет TypeScript и создаёт `dist/` для игры: прозрачный фон,
UI, PrismaUI bridge и `theme.user.css`. Проверка артефакта отклоняет попадание
dev-данных, localStorage и стенда. `npm run build:demo` отдельно создаёт `dist-demo/`.
Игра не требует Node.js, Vite server или доступа к CDN. Загружать нужно `index.html`
из всей папки `dist`, сохраняя относительное расположение assets.

## Что работает

- Пассивный чат, ввод, закрытие, fade, время сообщений и цвет каналов.
- Общая вкладка и фильтры каналов, отдельный канал отправки и unread-счётчики.
- Системные объявления без игрока-автора; канал только для чтения.
- Начальный снимок и добавление сообщений, история до 500 строк, дедупликация.
- Собственная отправка сразу видна затемнённой UI-строкой; серверная публикация заменяет её. Отказ оставляет текст с кнопкой повтора.
- Просмотр истории не сбрасывается новыми сообщениями; переход к непрочитанным.
- Онлайн, профиль, базовая статистика текущего представления.
- Fade, масштаб, шрифт, межстрочный интервал, фон, тема, временные метки и формат имени.
- Закрепление, перетаскивание за заголовок, resize за угол и ограничение окном экрана.

На стенде Enter или кнопка открывает чат; новая публикация не захватывает фокус.
Группа/гильдия/личные сообщения на стенде — демонстрационные каналы, не новые
возможности сервера. Кнопка «Отклонить следующую отправку» проверяет ошибку в строке
и ручной повтор. Настройки стенда сохраняются локально в браузере. В игре сохранение
передаётся native host и должно идти в TOML по выбранному конечным клиентом пути.
UI не сообщает об успешном сохранении до ответа host.

## Bridge v1

Типы: [bridge/types.ts](src/bridge/types.ts). UI-модели не являются protobuf-схемой.
Идентификаторы передаются строками, включая uint64. JSON — формат внутрипроцессного
bridge, не формат конфигурационного файла. Код приёма регистрируется до React mount.

Native host создаёт view, регистрирует JS listener `dreamsleeveCommand`, затем
передаёт снимок через `InteropCall(view, "dreamsleeveReceive", json)`.
Если listener отсутствует, команда не теряется молча: UI сохраняет текст в строке с ошибкой и
показывает ошибку. Вызовы из callback нужно маршалить на основной поток владельца
ClientApplication. Не вызывать его методы непосредственно с неизвестного потока.

| Host → UI | Смысл |
|---|---|
| `snapshot` | Каналы, последние сообщения, онлайн, selfId, serverName и необязательные settings |
| `messages` | Новые авторитетные публикации; пакет максимум 500 сообщений |
| `players` | Текущий список метаданных онлайна; без потока координат |
| `activate` / `deactivate` | Native focus получен / освобождён |
| `connection` | Изменение состояния соединения |
| `sendResult` | requestId + messageId при успехе либо requestId + error при отказе; это не публикация |
| `settingsResult` | Подтверждение записи настроек с revision или ошибка |

| UI → host | Смысл |
|---|---|
| `sendChat` | channelId, text, requestId корреляции UI |
| `close` | Освободить native focus; игру не ставить на паузу |
| `saveSettings` | Полный набор UI settings и монотонная revision |

UI requestId относится к lifetime данного view. Host сопоставляет его с RequestId,
который создаёт клиентское приложение; не подставляет его прямо в wire-пакет.
Ответы обрабатываются асинхронно. При уничтожении view его callbacks и отображение
корреляций удаляются, чтобы старый ответ не попал в новый интерфейс. При reconnect
host выдаёт новый снимок. При разрыве pending сохраняется с пометкой «Доставка неизвестна»;
UI не повторяет отправку автоматически, поскольку публикация могла уже состояться.

Native host — источник полномочий: он допускает каналы и публикации, проверяет
команды и не позволяет клиенту создать системное объявление. UI также скрывает
read-only каналы из отправки, но это не серверная проверка прав. Новые серверные
анонсы потребуют отдельного изменения протокола; текущий host должен объявлять
только реально поддержанные каналы. Некорректное событие bridge не применяется.
Текст сообщений выводится как текст, HTML не исполняется.

Настройки host валидирует и записывает атомарно через временный файл в TOML.
Не сохранять на каждом mousemove: UI посылает одну команду по окончании drag/resize.
Обычные настройки применяются сразу и записываются кнопкой «Сохранить настройки».
Ошибка записи оставляет настройки применёнными до закрытия, но явно отображается.
Пример будущей TOML-секции — [ui.example.toml](ui.example.toml); это контракт для
native host, существующий LoadClientSettings пока не читает эту секцию.

Автор текущего сообщения отображается из снимка профиля в самой публикации.
DisplayName и DisplayName@Username поддержаны. Имя персонажа намеренно не берётся
из онлайна для старой истории; это отложенная задача протокола.

## Темы и layouts

`views/` содержит TSX-разметку, `features/` — поведение ввода/fade/геометрии,
`state/` — операции представления, `styles/` — структурный CSS, `themes/` — палитру.
Layout выбирается в `views/App.tsx`; `layouts/SkyrimLayout.tsx` можно заменить
другим компонентом с props `{ chat: Chat }`, переиспользовав hooks и отдельные views.
Не нужно изменять native bridge, state или модели сообщений.

CSS-тему можно установить без пересборки, изменив `dist/theme.user.css`:

```css
[data-part="chat"] {
  --accent: #aad0e0;
  --ink: #f4f4ef;
  --border: #6c929f;
  --surface: 12, 20, 26;
  --system: #f4d98c;
}
[data-part="message"][data-channel="guild"] { --channel-color: #a3d3a3; }
```

Публичные части: `chat`, `header`, `messages`, `message`. Атрибуты:
`data-channel`, `data-source`, `data-active`, `data-theme`, `data-full-color`.
Все токены палитры перечислены в `themes/skyrim.css`; UI также передаёт
`--chat-font`, `--chat-font-size`, `--chat-line-height`, `--chat-background`.
Не привязывать пользовательский CSS к хешированным именам CSS Modules.
Собственные локальные шрифты подключаются через `@font-face` в файле темы;
следует предоставить кириллицу и учитывать лицензию выбранного шрифта.

CSS themes и замена layout при сборке — разные возможности. Универсального
исполнителя HTML-шаблонов и внешнего пользовательского JavaScript в игре нет.

## Следующая граница проверки

Подключение C++ host к ClientExchange, TOML-записи и игровому вводу остаётся шагом
native/SKSE-интеграции. После него необходимы реальные проверки PrismаUI: cursor,
Enter/Escape, раскладки/IME, потеря фокуса, UI reload и стоимость CPU-отрисовки.
Прохождение Playwright в Edge не является подтверждением этих свойств.

## Большое меню и метаданные игроков

Кнопка ☰ в заголовке и счётчик онлайна открывают отдельное центрированное окно.
Онлайн, профиль, статистика и настройки переключаются внутри него. Окно не является
дочерним элементом перемещаемого чата: положение, resize и масштаб чата его не меняют.
Tab остаётся внутри открытого меню, Escape возвращает в чат. На узком экране
колонки перестраиваются, длинное содержимое прокручивается внутри окна.

Player в UI bridge теперь допускает zone, race, nearbyMarker/markerKind, interior,
activity/activityTarget, lockDifficulty, menu, gameStartedAt и actorValues.
ActorValue имеет key, name и value: число либо { current, maximum }. Все имеющиеся
показатели показываются в карточке; здоровье/магия/запас сил выделяются шкалами.
Отсутствие показателя не подменяется нулём, уровень 0 допустим. Значения не обрезаются,
только визуальное заполнение шкалы ограничено 0..100%. Координаты не требуются.
Это представление уже имеющейся телеметрии, не расширение серверного протокола.

connection может включать phase: disconnected/authenticating/connecting/opening/
connected/disconnecting/faulted. connected=true допустимо только для connected.
Подпись состояния читается непосредственно в чате; потеря соединения не скрывается fade.

На браузерном стенде кнопка сохранения записывает настройки в localStorage этого
origin, включая положение/размер после drag/resize. Перезагрузка страницы их восстанавливает.
В game build localStorage отсутствует; host обязан сохранить TOML и подтвердить запись.
Имя сервера пока не имитируется: получение и отображение добавим после web UI,
вместе с соответствующим контрактом native/server.

Онлайн имеет переключатель «Карточки / Список». Выбор сохраняется вместе с настройками
(`onlineView`) сразу после переключения. Список показывает игрока в одной компактной
строке: имя/персонажа, уровень, зону/локацию, занятие и HP/MP/SP. Полные метаданные и
прочие actor values доступны по нажатию на имя. Заголовки закреплены при прокрутке;
длинные значения сокращены с tooltip, на узком экране прокручивается только таблица.
Кнопка «48 игроков онлайн» на dev-стенде позволяет оценить плотность списка.

Пассивный режим использует отдельный fade для каждой полученной публикации.
Новая строка не возвращает яркость старой истории и не раскрывает фон/рамку чата.
Задержка отсчитывается от локального получения; повторная доставка не продлевает её.
История из начального снимка не вспыхивает как новые сообщения. Enter раскрывает
всю историю, Escape освобождает фокус и возвращает пассивный режим. Крестика скрытия
в чате нет; SKSE управляет полным скрытием через JS Hide/Show (см. ниже)
или видимостью самого PrismaUI view.
Кнопка закрытия большого меню лишь возвращает пользователя в чат.

В подключённом пассивном режиме заголовок, подсказка, фон, рамка и элементы управления
полностью невидимы: появление публикации показывает только её строку поверх игры.
Ошибка соединения остаётся отдельным видимым уведомлением.

## Имя сервера и ожидание отправки

`[Server] ServerName = "Голоса Тамриэля"` в серверном TOML попадает в
`SessionOpened.server_name`, затем в `ClientOutput.status.serverName`. Host передаёт
его как `snapshot.serverName`: заголовки чата и большого меню используют это значение.
До welcome показывается Dreamsleeve. Пустое имя от старого сервера допустимо;
поле protobuf добавлено без смены версии wire-протокола.

`ClientOutput.chatConfirmations` сохраняет generation, requestId и messageId из
авторитетной собственной публикации. В одном Drain host сначала обрабатывает смену
сессии/снимок, затем подтверждения (с переводом native requestId в UI requestId),
затем дельты сообщений. Идентификаторы uint64 в JS передаются строками.
Снимок тоже может уже содержать подтверждённое сообщение; оба порядка поддержаны.
Ошибки `commandFailures` и `rejections` преобразуются в `sendResult.error`.
Обрыв транспорта означает неизвестную доставку, а не подтверждённый отказ.

Pending — только представление UI, не запись в ClientModel или серверной истории.
Строка затемнена до совпадения messageId; совпадение текста не используется.
Через 15 секунд ожидания или при разрыве появляется «Доставка неизвестна»;
позднее подтверждение всё ещё обрабатывается. Автоматических повторов нет.
«Повторить» доступно только после явного отказа и создаёт новый requestId.
Неопределённую строку можно убрать; ручная повторная отправка может создать дубль.
Одновременно допускается одна ожидающая отправка, до 16 сохранённых проблемных строк.
При смене сервера/пользователя строки очищаются; при reconnect того же пользователя
сверяются известные messageId со снимком. При пересоздании view локальные статусы
не сохраняются. Pending не подсвечивает фон и рамку пассивного чата.

Нативный PrismaUI host пока не реализован: Core предоставляет данные и корреляцию,
веб-стенд демонстрирует bridge; реальное соединение UI с Core — задача SKSE-адаптера.

## Скрытие для меню Skyrim

После загрузки JS доступны `Hide()` и `Show()`:

```cpp
prisma->Invoke(view, "Hide()");
prisma->Invoke(view, "Show()");
```

Те же действия доступны через `dreamsleeveReceive` как `{ "type": "hide" }`
и `{ "type": "show" }`. Это отдельное transient-состояние, не настройка TOML.
Hide сразу убирает чат и большое окно, отменяет взаимодействие/перетаскивание,
сохраняет историю, настройки, черновики и pending. Данные продолжают приниматься;
snapshot, ошибка соединения и activate не отменяют скрытие. Повторные вызовы безопасны.
Show возвращает пассивный чат; для ввода нужен отдельный activate после получения
native focus. Возраст сообщений продолжает отсчитываться во время скрытия.

Если чат был активен, Hide отправляет команду close для освобождения native focus.
SKSE-адаптер должен также самостоятельно освободить фокус Prisma при входе в меню:
DOM-скрытие не управляет захватом клавиатуры движком. Hide действует и без listener.
Выбор разрешённых меню, включая loading, делает SKSE; UI не знает меню игры.
При перекрывающихся меню вычисляйте итоговую видимость по всему текущему набору,
как в примере TrueFlasksNG, а не вызывайте Show на каждое отдельное закрытие.
Первый Hide можно вызвать после готовности JS до передачи snapshot; при пересоздании
view адаптер заново передаёт текущую видимость. По умолчанию view видим.
