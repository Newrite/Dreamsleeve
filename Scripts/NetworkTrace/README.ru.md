# Сетевая диагностика Dreamsleeve (Windows 10/11)

Установка анализатора не нужна. Откройте PowerShell **от имени администратора**, перейдите в каталог этих скриптов.
На клиенте укажите внешний IP сервера, на сервере — внешний IP клиента:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1 -PeerAddress 203.0.113.10
```

Адрес в примере замените. Запустите запись на обоих компьютерах перед подключением к игре. Дождитесь проблемной загрузки/обновления модели, запомните время и выполните на обоих компьютерах:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Stop.ps1
```

Результат в `network-traces/<UTC-время-ID>/` рядом со скриптами. Скрипт останавливает только свою именованную сессию. Каталог можно задать параметром `-OutputDirectory`; у Start и Stop он должен совпадать. Перезапуска Windows не требуется. Не удаляйте active.json до остановки: в нём имя сессии для восстановления.

Запись TCP фильтруется по IP, а не порту (этот вариант netsh не имеет TCP.Port). Сохраняются первые 128 байт пакета: это не полные модели, но здесь **могут быть фрагменты HTTP-заголовков и токенов**. Передавайте архив приватно, не публикуйте его. Не включаются дополнительные сценарии InternetClient/WinHTTP, способные записать полные заголовки.

Режим single, maxSize=0: начало сессии не затирается, произвольного лимита длительности/размера нет. Остановите запись после воспроизведения: файл растёт до остановки, свободное место всё же ограничено. ETL сохраняется как есть; конвертация и анализ выполняются отдельно. Захват пакетов на локальном loopback может отличаться от реального сетевого интерфейса — основной тест проводится между двумя компьютерами.

Приложите папку трассы **и** полную соответствующую сессию диагностики:

- клиент: `Data/SKSE/Plugins/Dreamsleeve/phantom-diagnostics` (в MO2 обычно мод Output_SKSE/overwrite), нужен диагностический клиент с `phantomDiagnostics = true`;
- сервер: `diagnostics` под рабочим каталогом сервера с `DiagnosticsEnabled = true`;
- DreamsleeveClient.log и время наблюдаемой задержки.

Настройки скрипты не меняют, чужие сессии не останавливают, записи не удаляют. При ошибке запуска сохраните start.log; при ошибке остановки состояние остаётся для повторной попытки. Если запуск точно не состоялся и netsh подтверждает отсутствие именованной сессии, active.json можно убрать вручную, сохранив остальную папку.

HTTP-события `http` содержат transfer, generation, направление, размер и прогресс. Клиент разделяет send (включая DNS/connect/TLS), headers, budget, body и EOF. Сервер разделяет ожидания peer/global budget, storage и чтение/запись Body. body_complete сервера означает завершение записи в HTTP-поток, а не подтверждённое получение клиентом. Тайминги накопительные; редкие промежуточные события пишутся примерно раз в секунду и после операций от 250 мс. Зависшая операция видна по предыдущей фазе; её длительность появится после завершения. Серверное elapsed_ms начинается с выдачи разрешения передачи, клиентское — с запуска HTTP job. Сопоставляйте события по transfer и поколению, а не только по часам разных компьютеров.
