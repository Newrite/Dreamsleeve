# Пространственный индекс и пакетная репликация

Реализовано после нагрузочных измерений 27 сентября 2026. Новых измерений
производительности на этом шаге не проводили; прежние цифры относятся к v4.

## Область видимости

PresenceAgent остаётся единственным владельцем Latest/Published, dirty-набора
и двух пространственных индексов. Индексы разделены по полному WRLD/CELL FormKey
и трёхмерной сетке; размер ячейки равен серверному VisibilityDistance. Для нулевого
радиуса используется ячейка 1 unit, а точная проверка по-прежнему требует совпадения
координат. Double-координаты ячеек исключают переполнение целых при любых конечных
float32 координатах и радиусах.

Latest-индекс обновляется при принятии состояния, Published — только после всей
публикации. Для наблюдателя берётся объединение соседних ячеек вокруг прежней и новой
позиции, затем проверяется точное расстояние с включённой границей. При движении
наблюдателя проверяются также неподвижные источники; иначе — изменившиеся соседи.
Self добавляется отдельно. Поэтому сохраняются выход, повторный вход, отсутствие
собственной позиции и одновременное перемещение нескольких игроков.

Профиль, имя, поколение и metadata рассылаются глобально, независимо от индекса.
Snapshot/Joined/Updated используют ту же точную проекцию видимости. Удаление игрока
убирает его из обоих индексов; неуспешная доставка не позволяет позднее послать
его координаты после Left в той же пачке.

Постоянная память индексов O(N); кандидаты строятся по одному получателю, без
сохранения графа всех пар. Работа зависит от соседей в проверяемых ячейках.
Полностью плотная группа всё ещё требует O(N²) проекций и координат; индекс
не отменяет стоимость глобальных metadata и начального снимка.

## Путь пачки

Presence → PlayerSession → runtime получает одно событие движения на получателя
за flush. Пачка содержит только изменившиеся видимые положения и очистки.
Смена профиля/поколения остаётся полным PlayerUpdated перед последующим движением.
PlayerSession сохраняет существующую очередь с ограничением и барьер открытия.

Runtime держит на маршруте ограниченный словарь ожидающего движения: максимум
MaxSessions разных источников. Пока данные не переданы транспорту, следующий замер
того же игрока в том же пространстве заменяет предыдущий. Словарь отправляется
на следующем transport Tick. Очистка или смена пространства для уже ожидающего
источника сначала отправляет прежнюю пачку. Любое другое исходящее сообщение
также завершает ожидающую пачку, сохраняя FIFO для metadata, поколений, Left,
ответов и чата. При закрытии маршрута оставшиеся неотправленные замеры удаляются.

Уже переданные ENet reliable-пакеты не изменяются. Медленный получатель всё ещё
может быть отключён существующими ограничениями; увеличение очередей не входит
в эту доработку. Параллелизм и новые агенты не добавлялись.

## Протокол v5 и C++

ServerPacket.players_moved (19) содержит PlayersMoved с repeated PlayerMoved players.
Номер 17 и имя player_moved старой одиночной ветки зарезервированы. RequestId
у пачки отсутствует; пустая пачка недопустима. В каждой записи player_id ненулевой,
а отсутствие location означает очистку. Порядок записей сохраняется.

Сервер режет пачки по границам записей с учётом всего сериализованного конверта
и MaxPacketBytes. Одна слишком большая запись приводит к ошибке до отправки
любой части этой пачки. Настройки транспорта и лимиты пакета остаются общими
с существующим конфигом; ENet fragmentation не заменяет прикладной лимит.

C++ сначала декодирует и проверяет всю пачку, затем применяет записи к ClientModel
и публикует результат в ClientExchange один раз. История движения и интерполяция
сохраняются. Клиент и сервер должны обновляться вместе: v4 отклоняется на входе.

## Проверки

Существующие проверки AOI дополнены сравнением дельт с точным расстоянием при
отрицательных координатах, переходах через ячейки и крайних float32 значениях.
Отдельно проверены пакет из нескольких источников, деление по лимиту protobuf,
отказ неделимой записи, объединение ожидающих замеров, clear/space/Left-барьеры,
ограничение словаря, приём нескольких игроков и одна публикация на C++ стороне.
Матрица бенчмарков повторена: [результаты v5](benchmarks/movement-v5-2026-09-27.md).

Проверено: 263 managed-теста, 202 C++-теста и 19 сценариев ENet smoke.
Отдельный нагрузочный прогон: 11/12 случаев сошлись по конечному состоянию,
из них два сильно деградировали; dense/1000 завершился ошибкой.
