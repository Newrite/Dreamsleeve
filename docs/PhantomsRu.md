# Фантомы: нативная модель Skyrim

Актуальная ветка — `codex/phantom-native-nif`, основана на полной функции
`codex/phantom-replication` (`3b80b8e`). Проверенный локальный прототип
`codex/phantom-local-se` (`23ae14d`) служит источником native clone/NiStream,
нормализации костей, оформления и применения поз. Протокол — **22**,
asset format — **2**; обе стороны обновляются одновременно.

## Модель и владельцы

Фантом — временная нативная сцена без Actor, AI, физики, постоянного REFR
или контроллеров. Игра создаёт геометрию, скины и материал, NiStream сохраняет
и восстанавливает их. Dreamsleeve передаёт отделённый NIF и меняет нативные
world transforms/bounds. Своих вершинных буферов, CPU skinning, извлечения
масок, реконструкции материалов/геометрии и GPU readback/upload нет.

| Ответственность | Владелец |
|---|---|
| Неизменяемая идентичность содержимого, поколение, доступность публикации | Server.Domain `Phantoms`; клиентские `Types` |
| Текущая сессия/публикация и данные remote | Client.Core `Exchange` |
| Кодек и проверенный asset | Client.Core `Codec`, `Nif`, `ValidatedAsset` |
| Рабочая очередь/отмена и отделённые данные | `Worker`; epoch/revision от Exchange |
| Reliable передачи/ACK/request correlation | `Streaming` |
| Файлы и кеш | существующие storage/worker, без игрового доступа |
| AOI, subscribers, ready/pending publication | существующий серверный `PhantomAgent`, один actor |
| Игровой источник/handle и завершение обновления | Game `PhantomCapture::Source` |
| Владение восстановленной NiPointer-сценой | Game `PhantomScene::Scene` |
| Выбор current/candidate и представление | Game `Phantoms`; UI читает состояние |
| Адреса, ABI, выделение NiStream/нормализация bone cookie | `Hooks.ixx` |

`ValidatedAsset` нельзя создать в обход Parse: он объединяет NIF с проверенной
таблицей ссылок. Нативная загрузка принимает только этот тип. Готовность данных
remote выводится из варианта content, готовность нативной сцены — из её фазы
Waiting/Loaded/Posed. Это разные ресурсы, не копии одного флага готовности.

## Capture → NIF → нативная сцена

Игровые операции выполняются после `Main::Update` на зафиксированном игровом
потоке. TESObjectREFR удерживается через `ObjectRefHandle`; нативные деревья —
через `NiPointer`. Worker получает только byte vectors и значения поз.

1. Берётся третье лицо `Get3D(false)`, независимо от камеры.
2. Clone проверяется на независимость узлов, метаданных, shader properties
   и изменяемых skin links. Особый массив клона BSFlattenedBoneTree переносится
   в корректное владение без ошибочного array cookie.
3. Оптимизированные skin transforms материализуются в NiNode; actor-only
   контейнеры заменяются обычными NiNode, skin roots/bones перенаправляются.
4. Удаляются extras, collision, controllers, lights и проверенные вспомогательные
   decal/weapon-blood/overlay/helper поверхности. Неизвестная значимая поверхность
   даёт явную ошибку; лицо или броня не пропускаются для объявления успеха.
5. На отделённом клоне применяется оформление прототипа: белая текстура
   `textures/effects/fxwhite.dds`, additive alpha, цвет/прозрачность, emissive/rim.
   Авторские texture sets очищаются до Save; материал остаётся нативным.
6. NiStream Save выдаёт независимый буфер. Он проверяется и передаётся worker
   для Zstd3, SHA-256 и хранения/доставки.
7. Получатель проверяет compressed hash/length, распаковывает и проверяет NIF
   до engine Load. NiStream создаёт сцену на игровом потоке. После Load
   проверяется порядок/родители/типы узлов, чинятся boneWorldTransforms,
   задаётся оформление, затем применяется полная поза и сцена присоединяется.

Общий локальный replay использует те же production ReadAsset/ReadSnapshot,
`Scene::Begin/Advance/Apply`, что сеть. Отдельного диагностического renderer нет.

Переносимость означает отсутствие ссылок на armor/face NIF автора и его
пользовательские texture paths в принятом asset. Получателю нужна штатная
белая текстура игры. Изменённое оформление после очищения всех авторских
текстур ещё требует визуального сравнения, особенно alpha волос и глаза.
Успешная проверка файла сама по себе не доказывает эквивалентность внешности.
Неизвестный non-node объект или пропущенная обязательная geometry clone pair
даёт явную ошибку вместо успешного неполного снимка. Отказ native Load помнит
view/generation в Game и не повторяет тяжёлую загрузку каждый кадр.

## Граница загрузки

Допускается stream100, NIF20.2.0.7, little-endian, user12. Поддержаны NiNode,
BSTriShape/BSDynamicTriShape/BSSubIndexTriShape, lighting/alpha/empty texture
set и стандартные skin instance/data/partition. Проверяются длины блоков,
типы ссылок, единственный root, дерево без циклов/общих детей, конечные числа,
размеры буферов/индексы, карты/число костей, partition links, отсутствие хвоста.
Extras, controller/collision/effect ссылки и внешние texture paths запрещены.
Это проверка нативного asset; формат вершин остаётся движковым.

Парсер ограничивает raw128 МиБ, compressed64 МиБ и4096 узлов. Глубина дерева
не более256. Это ограничения ресурсов, а не обещание вместимости в RAM/GPU.
Scene резервирует консервативную оценку `asset.MemoryBytes + 4*NIF + 1024*blocks`;
она включает предполагаемые native arrays/buffers/scratch, но не является
измерением resident memory драйвера. Старый и новый asset/scene учитываются
одновременно. При нехватке бюджета замена ждёт/отклоняется без уничтожения
пригодной старой сцены. Диск кеша по умолчанию1 ГиБ, общий RAM бюджет512 МиБ.

## Позы

Целевая частота20 Гц. Планировщик продвигает прежний deadline кратно периоду;
пропущенные слоты пропускаются, одинаковые catch-up кадры не создаются.

Каналы определяются из проверенной структуры: root, геометрия, skin roots
и кости; порядок — preorder NIF. Идентичность не зависит от адреса или имени.
В потоке передаются generation/context/sequence/sample time, origin,
полные TRS/hidden выбранных каналов и текущие world bounds геометрии.

Payload: заголовок60 байт, канал23 байта (XYZ int32 с шагом1/16 относительно
origin, quaternion int16×4, scale uint16 с шагом1/1024, hidden uint8), bound16
байт (относительный центр int32×3, radius float32). Каждый пакет независимо
сжат Zstd1; базы/дельты предыдущего unreliable пакета нет. Максимум raw256
КиБ/compressed128 КиБ. После декодирования quaternion нормализуется.

Получатель интерполирует с задержкой100 мс и ограничивает экстраполяцию100 мс.
Bounds интервала консервативно объединяются, при применении добавляется0,055
единицы на округление центра. Контейнерные spheres и VR occlusion boxes
пересчитываются снизу вверх; skin frameID инвалидируется для нативного skinning.
Общий envelope будущей записи не используется для живого потока.

World положение намеренно остаётся в позе. Movement обслуживает AOI и подписи;
его последнее значение не подставляется в отдельно пришедшую позу. Временная
связь потоков для безопасного удаления дублирования пока не определена.

## Изменение внешности

Transform, reparent оружия, hidden/fade и камера не входят в structural stamp.
При неизменной нативной геометрии это только позы. Смена root/набора mesh/skin
partition означает новое поколение. `TESEquipEvent` лишь запрашивает аудит;
SKSE NiNode update после UpdateEquipment отмечает ревизию. Пересборка происходит
позже, после стабильного наблюдения, а не внутри callback.

Страховочный аудит каждые250 мс ограничен4096 узлами и32 точками на dynamic
mesh; он сравнивает состав, ссылки и квантованные точки, не сериализует всё
дерево по таймеру. Изменение должно стабилизироваться750 мс; ошибка даёт retry1с.
Реальная редкая деформация публикует новый NIF. Непрерывная мимика не вызывает
передачи всех вершин каждый кадр. Покрытие модов, изменяющих только GPU или
непопавшие в выборку вершины, не гарантируется; flush callback RaceMenu является
очередью задач, а не гарантией завершения и не используется как такая гарантия.

## Передача и жизненный цикл

Models — reliable lane3, chunks16384 байт, ограниченное окно и число передач.
Poses — unreliable sequenced lane4 с `UNRELIABLE_FRAGMENT`. При rolloverFFFF
пустой reliable marker меняет транспортную эпоху; полезная поза остаётся
unreliable. Приложение получает только полностью собранный снимок. Control/chat
имеют собственную delivery policy и не ждут моделей.

Сервер не распаковывает NIF: хранит compressed content по SHA-256. IO вынесено
из actor. RequestId, session epoch, publication revision, source connection,
AOI view и generation исключают поздние завершения и возврат старой сцены.
Опубликованное поколение неизменно. Новый Publish сохраняет старые Ready/Latest
до commit; неуспех сохраняет прежнюю модель. Replacement Offer не посылает
Remove; смена контекста, AOI departure и отписка посылают Remove.

Бюджеты по умолчанию: клиент5 МиБ/с upload и отдельно5 МиБ/с download; сервер
5 МиБ/с общий model upload+download и5 МиБ/с на peer для обоих направлений.
Позы:2 МиБ/с на ingress источника и egress получателя,32 МиБ/с общий egress.
Ограничение числа фантомов по умолчанию4; оно не обещает доставку20 Гц при любой
численности игроков и bandwidth. Полные benchmark условия записываются отдельно.

Outdoors контекст — WRLD, indoors — CELL. Соседняя наружная CELL одного мира
не завершает поток. Пропавшее3D допускает ожидание. Save load, смена мира/
интерьера, disconnect и shutdown очищают ресурс в правильном контексте.
При замене сцена сохраняется, пока контекст действителен; обычный поток без
поз скрывается через timeout. Политики ignore, имён, streamer mode, расстояния,
боя и fallback светлячка переиспользуются из текущего Host/UI.
