# Фантомы: нативная модель Skyrim

Актуальная ветка — `codex/phantom-native-nif`, основана на полной функции
`codex/phantom-replication` (`3b80b8e`). Проверенный локальный прототип
`codex/phantom-local-se` (`23ae14d`) служит источником native clone/NiStream,
нормализации костей, оформления и применения поз. Протокол — **23**,
asset format — **2**; обе стороны обновляются одновременно.

## Модель и владельцы

Фантом — временная нативная сцена без Actor, AI, физики, постоянного REFR
или контроллеров. Игра создаёт геометрию, скины и материал, NiStream сохраняет
и восстанавливает их. Dreamsleeve передаёт отделённый NIF и меняет нативные
world transforms/bounds. Своих вершинных буферов, CPU skinning, извлечения
масок, реконструкции материалов/геометрии и GPU readback/upload нет.

| Ответственность | Владелец |
|---|---|
| Неизменяемая идентичность содержимого, поколение, доступность публикации | Server.Domain `Phantoms`; клиентские `Types` |
| Текущая сессия/публикация и данные remote | Client.Core `Exchange` |
| Кодек и проверенный asset | Client.Core `Codec`, `Nif`, `ValidatedAsset` |
| Рабочая очередь/отмена и отделённые данные | `Worker`; epoch/revision от Exchange |
| Reliable передачи/ACK/request correlation | `Streaming` |
| Файлы и кеш | существующие storage/worker, без игрового доступа |
| AOI, subscribers, ready/pending publication | существующий серверный `PhantomAgent`, один actor |
| Игровой источник/handle и завершение обновления | Game `PhantomCapture::Source` |
| Владение восстановленной NiPointer-сценой | Game `PhantomScene::Scene` |
| Выбор current/candidate и представление | Game `Phantoms`; UI читает состояние |
| Адреса, ABI, выделение NiStream/нормализация bone cookie | `Hooks.ixx` |

`ValidatedAsset` нельзя создать в обход Parse: он объединяет NIF с проверенной
таблицей ссылок. Нативная загрузка принимает только этот тип. Готовность данных
remote выводится из варианта content, готовность нативной сцены — из её фазы
Waiting/Loaded/Posed. Это разные ресурсы, не копии одного флага готовности.

## Capture → NIF → нативная сцена

Игровые операции выполняются после `Main::Update` на зафиксированном игровом
потоке. TESObjectREFR удерживается через `ObjectRefHandle`; нативные деревья —
через `NiPointer`. Worker получает только byte vectors и значения поз.

1. Берётся третье лицо `Get3D(false)`, независимо от камеры.
2. Clone проверяется на независимость узлов, метаданных, shader properties
   и изменяемых skin links. Особый массив клона BSFlattenedBoneTree переносится
   в корректное владение без ошибочного array cookie.
3. Оптимизированные skin transforms материализуются в NiNode; actor-only
   контейнеры заменяются обычными NiNode, skin roots/bones перенаправляются.
4. Удаляются extras, collision, controllers, lights и проверенные вспомогательные
   decal/weapon-blood/overlay/helper поверхности. Неизвестная значимая поверхность
   даёт явную ошибку; лицо или броня не пропускаются для объявления успеха.
5. На отделённом клоне применяется оформление прототипа: белая текстура
   `textures/effects/fxwhite.dds`, additive alpha, цвет/прозрачность, emissive/rim.
   Авторские texture sets очищаются до Save; материал остаётся нативным.
6. NiStream Save выдаёт независимый буфер. Он проверяется и передаётся worker
   для Zstd3, SHA-256 и хранения/доставки.
7. Получатель проверяет compressed hash/length, распаковывает и проверяет NIF
   до engine Load. NiStream создаёт сцену на игровом потоке. После Load
   проверяется порядок/родители/типы узлов, чинятся boneWorldTransforms,
   задаётся оформление, затем применяется полная поза и сцена присоединяется.

Общий локальный replay использует те же production ReadAsset/ReadSnapshot,
`Scene::Begin/Advance/Apply`, что сеть. Отдельного диагностического renderer нет.

Переносимость означает отсутствие ссылок на armor/face NIF автора и его
пользовательские texture paths в принятом asset. Получателю нужна штатная
белая текстура игры. Изменённое оформление после очищения всех авторских
текстур ещё требует визуального сравнения, особенно alpha волос и глаза.
Успешная проверка файла сама по себе не доказывает эквивалентность внешности.
Неизвестный non-node объект или пропущенная обязательная geometry clone pair
даёт явную ошибку вместо успешного неполного снимка. Отказ native Load помнит
view/generation в Game и не повторяет тяжёлую загрузку каждый кадр.

## Граница загрузки

Допускается stream100, NIF20.2.0.7, little-endian, user12. Поддержаны NiNode,
BSTriShape/BSDynamicTriShape/BSSubIndexTriShape, lighting/alpha/empty texture
set и стандартные skin instance/data/partition. Проверяются длины блоков,
типы ссылок, единственный root, дерево без циклов/общих детей, конечные числа,
размеры буферов/индексы, карты/число костей, partition links, отсутствие хвоста.
Extras, controller/collision/effect ссылки и внешние texture paths запрещены.
Это проверка нативного asset; формат вершин остаётся движковым.

Парсер ограничивает raw128 МиБ, compressed64 МиБ и4096 узлов. Глубина дерева
не более256. Это ограничения ресурсов, а не обещание вместимости в RAM/GPU.
Scene резервирует консервативную оценку `asset.MemoryBytes + 4*NIF + 1024*blocks`;
она включает предполагаемые native arrays/buffers/scratch, но не является
измерением resident memory драйвера. Старый и новый asset/scene учитываются
одновременно. При нехватке бюджета замена ждёт/отклоняется без уничтожения
пригодной старой сцены. Диск кеша по умолчанию1 ГиБ, общий RAM бюджет512 МиБ.

## Позы

Текущий профиль по умолчанию — 10 Гц; 20 Гц остаётся настраиваемым. Планировщик продвигает прежний deadline кратно периоду;
пропущенные слоты пропускаются, одинаковые catch-up кадры не создаются.

Каналы определяются из проверенной структуры: root, геометрия, skin roots
и кости; порядок — preorder NIF. Идентичность не зависит от адреса или имени.
В потоке передаются generation/context/sequence/sample time, origin,
полные TRS/hidden выбранных каналов и текущие world bounds геометрии.

Payload: заголовок60 байт, канал23 байта (XYZ int32 с шагом1/16 относительно
origin, quaternion int16×4, scale uint16 с шагом1/1024, hidden uint8), bound16
байт (относительный центр int32×3, radius float32). Перед Zstd байты каналов и bounds обратимо
переставляются в отдельные байтовые плоскости (pose version3). Точность та же.
Каждый пакет независимо сжат Zstd1; базы/дельты предыдущего unreliable пакета нет. Максимум raw256
КиБ/compressed128 КиБ. После декодирования quaternion нормализуется.

Получатель использует общий `Client.PlayoutClock`: insertion владеет временем,
а чтение снимка не меняет состояние. Настроенные задержки (phantom100 мс,
movement150 мс) — минимумы. Цель — два интервала снимков плюс EMA джиттера;
автоматическая добавка ограничена историей и400 мс. У поз пропуски sequence
учитываются при оценке исходной частоты. Время не переставляется при каждом
пакете: скорость плавно корректируется (обычно0,98/1,02, при большом отклонении
0,85/1,10). Начальная настройка требует нескольких секунд накопления буфера.
Экстраполяция поз ограничена100 мс и предсказывает только перенос origin:
все world channels и bounds получают одинаковое смещение, articulation остаётся
последней полученной. Movement после конца истории удерживает положение.
Контекст/поколение, телепорт movement и длинный разрыв сбрасывают историю.
Владелец phantom history — Exchange; movement history — MovementView.

World положение намеренно остаётся в позе. Movement обслуживает AOI и подписи светлячков;
его последнее значение не подставляется в отдельно пришедшую позу. Временная
связь потоков для безопасного удаления дублирования пока не определена.

## Изменение внешности

Transform, reparent оружия, hidden/fade и камера не входят в structural stamp.
При неизменной нативной геометрии это только позы. Смена root/набора mesh/skin
partition означает кандидата нового поколения. TESEquipEvent и SKSE NiNode
update только запрашивают проверку: последний тоже может сообщать о queued
работе. Проверенный hook в завершённой ветви AIProcess::Update3DModel_Impl
запрашивает тот же аудит. Callback не читает сцену и не сериализует модель.

Аудит ограничен4096 узлами и32 точками на dynamic mesh. После уведомлений
и во время стабилизации — не чаще4Гц, в тишине — раз в секунду. Сравнение
идёт с принятым asset, а не с округлёнными ячейками координат/прошлым тиком.
Стабильный состав требует250мс; деформация — смещения >0,25 единицы модели
и1с устойчивости с допуском0,0625. Последний порог — измеренная эвристика
подавления малой динамики лица, не универсальное распознавание мимики.
Медленно накопленный морф обнаруживается относительно принятого asset.
Непрерывная мимика не передаётся потоком вершин. Отсутствующие в выборке и
GPU-only правки сторонних модов остаются ограничением. Ошибка даёт retry1с.

## Передача и жизненный цикл

В protocol26 Models — reliable lane3 только для небольших уведомлений,
допуска HTTP-передачи и завершения. Сжатый NIF передаётся PUT/GET на
`/phantoms/content` того же Kestrel/auth origin. Отдельный сервис, порт и nginx
не требуются. Сервер проверяет целый SHA-256 и публикует файл атомарно.

PhantomAgent владеет допуском, session/AOI/generation и Ready/Latest; HTTP registry
владеет одноразовым ключом, отменой и ходом I/O. Эти состояния не дублируют
готовность модели. Actor опрашивает прогресс/результат lease, не читает диск.
На Windows Http владеет ограниченными async WinHTTP jobs; callback только
сигнализирует владельцу задачи. Буферы живут до HANDLE_CLOSING. Streaming
совмещает HTTP тело и accepted ENet Complete по request/transfer identity;
после этого обычный Worker проверяет hash, декодирует и наполняет кеш.

Серверные ModelBytesPerSecond и PlayerModelBytesPerSecond (оба по умолчанию
5 MiB/s) ограничивают суммарные тела upload+download: первый для всего сервера,
второй для одного peer. Клиентские upload/download budgets отдельные, общие
для передач соответствующего направления, тоже 5 MiB/s. ChunkBytes теперь
только размер переиспользуемого файлового буфера; WindowChunks удалён из
конфига. Ограничения concurrency/storage/RAM сохранены. HttpRequestsPerMinute
(128 по умолчанию на IP) относится к числу файловых запросов, не к частям
тела и не к авторизации. Его следует настроить для многих игроков за одним NAT.

TCP управляет congestion/retransmission; собственное ENet ACK-окно/ModelFlow
и принудительное изменение ENet flight window удалены. Скорость не зависит
от фиксированного кредита на одном runtime tick. Server pose tick сохраняет
сетку периода: поздний вызов пропускает интервалы и отправляет последний снимок.
Poses — unreliable sequenced lane4 с `UNRELIABLE_FRAGMENT`. При rolloverFFFF
пустой reliable marker меняет транспортную эпоху; полезная поза остаётся
unreliable. Приложение получает только полностью собранный снимок. Control/chat
имеют собственную delivery policy и не ждут моделей.

Сервер не интерпретирует NIF: хранит compressed content по SHA-256; для дельты
восстанавливает полный asset на отдельной задаче. IO вынесено
из actor. RequestId, session epoch, publication revision, source connection,
AOI view и generation исключают поздние завершения и возврат старой сцены.
Опубликованное поколение неизменно. Новый Publish сохраняет старые Ready/Latest
до commit; неуспех сохраняет прежнюю модель. Replacement Offer не посылает
Remove; смена контекста, AOI departure и отписка посылают Remove.

На время замены source удерживает два поколения. Один пакет содержит новую
полную позу и optional previous_sample: другую полную позу старого NIF, снятую
в тот же момент и контексте. Каналы поколений никогда не сопоставляются по
индексу между разными NIF. Сервер принимает такой пакет уже во время upload;
получатель применяет подходящий sample к имеющейся сцене. Отсоединённая старая
геометрия может временно следовать сохранённой привязке к живому родителю.
Это допускает старое оружие в руке при новой анимации; удалённый skeleton/root
без сохранившихся нативных привязок так восстановить нельзя.

Клиент посылает Displayed(player, view, generation) после Apply+Attach новой
сцены. Сервер отвечает источнику Settled(generation, context), когда все текущие
выбранные подписчики подтвердили сцену или истёк TransferTimeoutMs после commit
(по умолчанию30с). Отписавшиеся больше не удерживают переход. До Settled новые
изменения объединяются в последующий актуальный захват: текущая загрузка не
отменяется из-за каждого equip. После таймаута медленный получатель может
остаться без свежей старой позы; применяются обычные timeout/fallback правила.
В переходе payload может удвоиться, но это всё ещё один snapshot/тик; общие
byte budgets учитывают полный пакет. Память обоих поколений зарезервирована;
нехватка места откладывает локальную замену, не вытесняя прежние сцены.

Обновление передаётся дельтой к предыдущему raw asset, если она меньше полного
архива и база доступна. Сервер восстанавливает и проверяет полный архив; новым
получателям отдаёт его, имеющим точную базу — сохранённую дельту. При cache miss,
смене контекста без Ready или ошибке apply используется полный asset. Нативная
сцена по-прежнему загружается целиком и заменяется после готовности; живые mesh
буферы не патчатся. Контракт: Protocol/README.ru.md, v26.

Бюджеты по умолчанию: клиент5 МиБ/с upload и отдельно5 МиБ/с download; сервер
5 МиБ/с общий model upload+download и5 МиБ/с на peer для обоих направлений.
Позы:2 МиБ/с на ingress источника и egress получателя,128 МиБ/с общий egress.
Ограничение числа фантомов по умолчанию4; оно не обещает доставку полной заданной частоты при любой
численности игроков и bandwidth. Полные benchmark условия записываются отдельно.

Outdoors контекст — WRLD, indoors — CELL. Соседняя наружная CELL одного мира
не завершает поток. Пропавшее3D допускает ожидание. Save load, смена мира/
интерьера, disconnect и shutdown очищают ресурс в правильном контексте.
При замене сцена сохраняется, пока контекст действителен; обычный поток без
поз скрывается через timeout. Политики ignore, имён, streamer mode, расстояния,
боя и fallback светлячка переиспользуются из текущего Host/UI.

## Профиль частоты и бюджета (07.10.2026)

Частоты уже имеют владельцев и настройки; нового независимого rate state нет.
Интерполяция выполняется на каждом кадре отображения, частота пакетов её не
ограничивает. Movement использует минимум задержки150 мс, phantom playback —100 мс
с адаптивным запасом и максимумом100 мс экстраполяции. Визуальное качество 10 Гц требует игрового QA.

| Где | Ключ | Default 10 Гц | Для 20 Гц |
|---|---|---:|---:|
| client.toml `[client]` | playerSampleIntervalMs | 100 | 50 |
| ui.toml `[ui.chat]` | phantomSampleRate | 10 | 20 |
| server.toml `[Runtime.Presence]` | ReplicationIntervalMs | 100 | 50 |
| server.toml `[Phantoms]` | PoseIntervalMs | 100 | 50 |
| server.toml `[Phantoms]` | ReplicationIntervalMs | 100 | 50 |

Pose capture использует минимум UI rate и серверной Policy. Movement-периоды
задаются независимо на обеих сторонах. Чтобы переключить весь профиль, нужны
все соответствующие значения. Пакетный формат и интерполяция не меняются.
Utils::Time::AdvanceSample переиспользуется Game/ClientRuntime/Streaming:
поздний кадр пропускает истёкшие интервалы, не сдвигает сетку и не создаёт burst
одинаковых снимков. Два потока всё ещё связываются временем/контекстом,
а не «последним movement» для произвольной позы.

`Phantoms.TotalPoseBytesPerSecond` теперь 134217728 (128 MiB/s, общий fanout),
`PoseBytesPerSecond` остаётся 2097152 (2 MiB/s на peer). Это лимиты, а не обещание
производительности хоста. Полный steady pose fanout 512×4×10 требует около
77 MiB/s до ENet/IP/UDP, временные пары поколений увеличивают его. Для профиля
20 Гц та же оценка около 154 MiB/s: лимит 128 также может ограничивать доставку.
Model budgets остаются 5 MiB/s суммарно/на peer; повышение pose budget их не меняет.
`ui.example.toml` поставляется рядом с client.toml; существующий ui.toml сохраняется.

## Очереди моделей и поз, 07.10.2026

Client Worker имеет два потока: ModelRun обслуживает сжатие/хеш/NIF validation
отделённых bytes и файловый кеш; Run — кодирование/декодирование поз и передачу
нового detached capture в одиночный заменяемый slot. Native Clone/Save/Load
остаются на игровом потоке. Exchange владеет prepared assets текущего и
удерживаемого поколения. Во время подготовки нового asset старые самостоятельные
позы продолжаются через последнюю подтверждённую сервером публикацию.
Завершения с устаревшими epoch/revision не меняют текущую публикацию.

TransportOwner хранит reliable Models FIFO по peer отдельно от Poses. Pose slot
идентифицируется recipient/source; замена сохраняет очередь обслуживания, обновляет
полный пакет и время поступления, учитывает только прирост байтов. Старее200 мс
пакет отбрасывается до ENet. Control/chat и обычный Realtime сохраняют приоритет;
после8 poses готовая model очередь получает ход. Blocked model peer не блокирует
его позы. На момент этого исправления использовался protocol24, asset2, pose3,
ENet unreliable sequenced fragmentation. `TransportPacket.Schedule` — локальная
метка очереди, не поле protobuf. Новый histogram `outgoing.pose.age` измеряет
ожидание каждого отправляемого/просроченного pose slot отдельно от model.

Уведомления модели имеют приоритет только на голове существующей per-peer FIFO:
В protocol26 эта FIFO содержит только уведомления, без Chunk. Для Offer/Remove очередь хранит счётчик
ещё не переданных уведомлений recipient/source; соответствующий latest pose ждёт
успешного ENet admission. Остальные источники продолжают отправляться даже при
blocked model. Это зависимость принятых команд очереди, не копия готовности сцены
или подписки. Порядок между ENet lanes на самой сети всё равно не гарантируется;
клиентские проверки view/generation и независимые полные snapshots сохраняются.

`LanePolicy.admissionLane` задаёт профиль квот handoff и native ENet. Для небольших
model notices используется reliable control reserve; wire lane остаётся Models.
Иначе заполнение pose очереди выше половины бюджета блокировало бы Offer в
bulk-квоте и останавливало fanout через pending outbox. Не-budget отказ native
reliable Send завершает peer, budget pressure остаётся повторяемой операцией.

При принятии нового Offer/Remove TransportOwner удаляет ещё не отправленный pose
slot предыдущего view того же recipient/source. Это устраняет отправку старой позы
сразу после нового уведомления. Фрагментированные poses используют realtime-квоту
и в managed handoff, и в native PacketBudget; тела моделей идут через HTTP.

PhantomAgent обновляет selection на прежнем ReplicationIntervalMs, но отправляет
позы малыми turns до25 мс. Per-source credit допускает два снимка для компенсации
джиттера и пополняется с частотой1/ReplicationIntervalMs. DispatchedPose хранит
только оплаченный generation/sequence: частичная рассылка той же позы не платит
повторно. Это состояние расписания, отдельно от Ready/Latest и watermark входа.
Общий FanoutCredit допускает MaxPoseFanoutPerTick отправок и пополняется на эту
величину за ReplicationIntervalMs. Каждый turn проверяет не больше этого числа
подписок, включая уже актуальные; сканирование может происходить чаще прежнего,
но сетевой потолок не умножается. Курсоры не двигаются без доступного общего кредита.
Проверены phase jitter, transient pressure, sustained overload и fairness.

## Доставка и подпись: исправление вечернего теста07.10.2026

Историческая реализация protocol24 (удалена при переходе на HTTP в25):
ENet transport owner для fragmented reliable sends поднимал sender flight ceiling
до512KiB только при unlimited native bandwidth. Это общее окно peer для всех
каналов, отдельно от прикладного окна32×16KiB на передачу; ACK/sequence windows,
packetThrottle, rate/lease budgets сохраняются. Явные native bandwidth limits
не переопределяются. [Замеры с RTT, loss и control](benchmarks/phantom-delivery-labels-2026-10-07.md).

Подпись фантома читает текущий world transform уникальной передаваемой кости
головы из `PhantomScene`, после интерполяции/Apply. Bounds остаются только для
отсечения. Кость выбирается при Load и принадлежит корню сцены; неоднозначное
или отсутствующее имя использует root+120×scale. Общие правила PlayerLabels и
смещение имени сохраняются; независимой интерполяции/UI-очереди не добавлено.
