# Принятые решения и состояние проекта

Dreamsleeve — социальный слой для Skyrim: общий чат и системный канал объявлений, онлайн с
игровыми показаниями, светлячки других игроков с именами и облачками сообщений, метки на
земле, модерация и веб-админка. Сервер — F# на .NET 10; клиент — C++23 (MSVC modules):
переносимое ядро `Client.Core`, SKSE-плагин `Dreamsleeve.Client` и консольный `Client.Dev`;
интерфейс — TypeScript/React в PrismaUI. В ветке `codex/phantom-native-nif`
модель фантома снова использует native clone/NiStream/NIF и native scene;
neutral geometry/material pipeline и CPU skinning удалены. Reliable model
streaming, independent unreliable poses, AOI, файловое хранилище и кеш
переиспользуются. Контракт protocol26: [PhantomsRu.md](PhantomsRu.md).
Автоматические проверки, результаты benchmarks и остающийся игровой QA
SE/AE/VR приведены в [отчёте выпуска](PhantomReleaseValidationRu.md).

Сверено 1 октября 2026 года с кодом. Это описание решений и состояния, а не поручение агенту.
Поздние явные решения и контракты кода (README рядом с кодом,
[Protocol/README](../Protocol/README.ru.md)) важнее ранних примеров в спецификациях и
справочниках ([ProductSpecRu](ProductSpecRu.MD), [DomainSpecRu](DomainSpecRu.MD),
[TechnicalHandbookRu](TechnicalHandbookRu.MD), [ProtobufHandbookRu](ProtobufHandbookRu.MD),
[SqlHandbookRu](SqlHandbookRu.md)): `nickname`, UUID-ключи, отдельный PositionSpace или
фиксированные level/health оттуда — не контракт. Навигация — [docs/README.md](README.md),
развёртывание и настройка сервера — [DeploymentRu.md](DeploymentRu.md).

## Принятые решения

### MVP и границы

- Первый результат: глобальный чат, онлайн со статами, именем персонажа и местом, светлячки
  других игроков. Поверх него сделаны объявления, метки на земле, модерация (словарь,
  антиспам, игнор, наказания, роль модератора), гильдии и веб-админка. Друзья, партии,
  личные сообщения и жалобы — следующие этапы ([ProductSpecRu](ProductSpecRu.MD)).
- Сервер ретранслирует наблюдения клиента и не симулирует игру: скорость, телепорты,
  диапазоны HP и причины смерти не проверяет. Исключение — мягкая проверка, что метку
  ставят рядом с последним известным положением автора.
- Сеть не зависит от игры: чат работает и в главном меню. `Client.Dev` и браузерный стенд UI
  позволяют разрабатывать без Skyrim, но не заменяют проверку в игре.

### Стек и границы модулей

- Сервер: F# / .NET 10, yENet (выбран вместо zENet), агенты
  [Dreamsleeve.Agent](../src/Dreamsleeve.Agent/README.ru.md) на Channels/Task, SQLite
  (Migrondi + SqlHydra), ASP.NET Core с Falco для HTTP, Serilog.
- Клиент: C++23 modules, xmake/MSVC, native ENet 1.3.18, protobuf, spdlog, Glaze; SKSE-плагин
  на CommonLibSSE-NG, SE/AE/VR в одной DLL, код с CommonLib только в `.ixx`
  ([MsvcProtobufModulesRu](MsvcProtobufModulesRu.md)). UI: TypeScript, React, Vite, Zustand;
  логика, разметка и CSS раздельно, один интерфейс для браузера и PrismaUI ([ClientUiPlanRu](ClientUiPlanRu.md)).
- `Client.Core` не зависит от Skyrim: DreamNet, домен, модель, кодек, AuthHttp,
  `ClientApplication`. SKSE-адаптер переводит игровые данные в доменные значения; второй
  модели, сетевого runtime и протокола в нём нет. `Client.Dev` — консольный клиент на том же
  `ClientApplication` (`--connect`) плюс синтетические `--state-demo` и `--movement-demo`.
- `Domain.Logic` (Core) — чистые правила на доменных значениях: расстояния и досягаемость,
  движение, слияние профиля, проверки ключей, мест и дат, вид канала, политика объявлений.
  Кодировки движка (имена `MARKER_TYPE`, сырой календарь, имена файлов плагинов) — в
  `Game/World.ixx` SKSE-плагина, не в Core.
- Общие помощники клиента — один модуль `Dreamsleeve.Client.Utils` с пространствами по темам
  (`Utils::Text`), без локальных копий. F# отделяет примитивы UMX и закрытыми представлениями
  с фабриками, C++ — алиасами и открытыми структурами. Магические числа — именованные
  константы владельца; код, нужный только тестам, живёт в тестах.

### Идентичность и имена

`PlayerId`, `ChatMessageId`, `ChatChannelId`, `GroundMarkId` — выдаваемые сервером ненулевые
`uint64`, не UUID. SQLite хранит их положительными INTEGER до `Int64.MaxValue`;
преобразование проверяется на границе хранения, домен не сужается.

| Значение | Контракт |
|---|---|
| `Username` | Уникальное имя входа; Trim, ASCII `A-Z a-z 0-9 _ .`, нижний регистр; `server`, `system` и префикс `hidden.` зарезервированы |
| `DisplayName` | Отображаемое имя; Trim + NFC, совпадения разрешены; игрок меняет его сам с интервалом |
| `CharacterName` | Необязательное имя персонажа как пришло из игры; не прошедшее словарь не публикуется |

- Уникальность `Username` обеспечивает хранилище профилей; фабрика проверяет только значение.
- Публичная личность — профиль или псевдоним (`PublicIdentity = Profile | Pseudonymous`),
  PlayerId открыт всегда. Сообщение хранит снимок профиля автора, сообщение и метка — снимок
  имени персонажа на момент отправки (`ChatMessage.character_name`); актуальный профиль UI
  получает отдельно. Метка показывает текущий профиль автора либо псевдоним, под которым её
  поставили.
- ID и время сообщения назначает сервер; порядок задаёт ID, а не время. Время на границах —
  Unix milliseconds `int64` (.NET `DateTimeOffset`, C++ `sys_time<milliseconds>`).
- Как показывать имена (username / display / персонаж, локальный режим стримера, игнор),
  решает одно разрешение `Host::Names::NameFor` в SKSE-host — для чата, онлайна, профиля и
  надписей в мире.

### Пространство и показания

- `FormKey = PluginName + LocalFormId`: плагин происхождения и локальный ID, без индекса load
  order. `PluginName` — только ASCII case folding, без Trim, NFC и проверки пути.
- `LocationId = FormKey`: WRLD в экстерьере, CELL в интерьере. Отдельного PositionSpace нет,
  BGSLocation даёт только подпись места.
- `PlayerLocation` — `Location`, XYZ `float` в единицах Skyrim и три угла в радианах.
  Отсутствующее положение не равно `(0, 0, 0)`. Расстояния — только внутри одного
  пространства, в `double`; для радиуса достаточно квадрата расстояния.
- Actor Value: ключ `namespace:name` (`skyrim:health`), подпись отдельно; `Scalar` или
  `Resource(current, maximum)`; значения вне диапазона сохраняются, clamping нет.
- Новый персонаж — новый `characterGeneration`; выход из игры сохраняет серверный профиль.
  Игровые данные (позиция, показания, детали) живут только в памяти сервера.

### Владение и проверки

- У каждого правила один владелец. Изменяемое состояние серверного агента видит только его
  обработчик; агент выполняет один обработчик за раз, отдельного потока на агента нет.
- На клиенте моделью, кодеком и ENet владеет один сетевой поток `ClientApplication`. Главный
  поток игры (или консоль Client.Dev) обменивается с ним только через `ClientExchange`:
  команды Post → TakeCommands, состояние Publish → Drain, без callbacks с сетевого потока.
  Игровые указатели через границу не передаются, адаптер отдаёт самостоятельные `Domain::*`.
- Каждая проверка делается один раз, на границе, где данные входят; дальше код доверяет
  проверенному и только измеряет или обрезает. Клиент хранит полученное от сервера без
  повторной валидации и нормализации.

| Слой | Проверяет |
|---|---|
| Сервер: доменные фабрики, кодек, сессия, владельцы | Строки, размеры, конечность чисел, словарь, права, частоту, содержимое запросов; отказ — `RequestRejected` этого запроса |
| Клиентский кодек, исходящие | Только то, из-за чего сервер закроет соединение: RequestId ≠ 0, UTF-8 всех строк (рефлексией protobuf), размер пакета |
| Клиентский кодек, входящие | Форму пакета: версия, payload, ненулевые ID, корреляция, размеры |
| `ClientRuntime` | Зависящее от сессии: поколение, Ready, порядок RequestId, канал и его вид, политика объявлений из приветствия |
| `ClientModel` | Операции: неизвестный игрок или канал, конфликт сообщения, ревизия видимых меток, поколение |
| SKSE-host | Корреляцию и размеры ввода страницы; строки игры чинит один раз `World::Text` → `Utils::Text::Repair` |
| Конфигурация | Сервер — один раз в `Configuration.validate` / `GameSettings.create`; клиент — `ValidateClientSettings`, который вызывает `DreamNetClient::ValidateConfig` и `ClientExchange::InvalidCapacity` |

### Сервер подтверждает собственные действия

Собственное действие клиента применяется тем же путём, что событие другого игрока: отправка
команды не меняет принятое состояние, optimistic update нет. Своё сообщение приходит обычным
`ChatMessagesReceived` с серверными ID, временем и профилем; отказ — `ServerRejection`, в
истории ничего не появляется. Так же устроены метки, смена режима скрытого имени (только
подтверждение меняет `hideIdentity` в `ui.toml`), смена отображаемого имени и своя телеметрия
в онлайне. Строки ожидания («Не отправлено», «Доставка неизвестна» через 15 с) существуют
только в UI; автоповтора нет.

### Ограниченные очереди

Все очереди ограничены числом элементов и имеют явный исход насыщения: `Full`/`Closed` у
команд клиента, `Overloaded` до изменения состояния на сервере, отключение только
перегруженного подписчика, новый снимок вместо потерянной цепочки дельт клиента. Служебные
сообщения (Stop, Detach, ответы входа) идут из резерва, не обгоняя принятые команды.
Realtime при насыщении можно пропустить, reliable — нет: отказ или закрытие соединения
наблюдаемы. Подробно: [Server.Core](../src/Dreamsleeve.Server.Core/README.ru.md),
[State](../src/Dreamsleeve.Client.Core/State/README.ru.md).

### Протокол и конфигурация

- Клиент и сервер поставляются вместе, обратной совместимости протокола нет: изменение
  контракта поднимает `protocol_version` и обновляет обе стороны,
  [Protocol/README](../Protocol/README.ru.md) и `ProtocolContract.cpp`; флагов поддержки и
  заглушек для старых клиентов нет. Текущая версия — 15.
- Коды отказа — общий `RequestRejectionCode` в `protocol.proto`; F# и C++ используют
  сгенерированные типы, ручных списков кодов нет.
- Пользовательские файлы (`server.toml`, `client.toml`, `ui.toml`) без новых ключей получают
  умолчания. Формат может меняться, но поставляемые `*.example.toml` полны (тесты сверяют их
  с умолчаниями); неизвестный ключ сервер отклоняет.
- Конфигурация, словарь и псевдонимы читаются при запуске, hot reload нет. Размер пакета и
  лимиты строк задаются конфигурацией и по сети не согласуются; политика объявлений
  (источники и лимиты) приходит в приветствии.

## Что реализовано

### Сервер: runtime и владельцы

`Dreamsleeve.Server` — composition root: SQLite, два HTTP-хоста (`Dreamsleeve.Server.Web`) и
`ServerRuntime` с `SessionTable` (маршруты ConnectionId, резервы PlayerId, книга псевдонимов,
роли, муты). Остальные владельцы: `PlayerSession` на соединение, два `ChatRoomAgent` (общий и
системный канал), `PresenceAgent`, `GroundMarksAgent`, `AuthService`, `AdminService`;
`TransportOwner` обслуживает ENet на своём потоке. Резерв PlayerId снимается только после
завершения старой сессии, подтверждений Detach от всех источников и освобождения транспорта.
Ошибка одного игрока изолирована; потеря общей зависимости останавливает runtime.
[Server.Core](../src/Dreamsleeve.Server.Core/README.ru.md), [домен](../src/Dreamsleeve.Server.Domain/README.ru.md).

### Транспорт и каналы ENet

Три канала: Control (0, reliable) — вход, команды, метаданные, границы видимости, метки;
Chat (1, reliable) — чат, объявления, удаление сообщений; Realtime (2, unreliable sequenced) —
позы. Общего порядка между каналами нет. Базовый период отправки клиента и репликации сервера —
50 мс (20 Гц), тики независимы. Сессия привязана к ENet-соединению: переподключение получает
новый bootstrap. Realtime-пачки делятся по MTU без reliable-фрагментации.
[SpatialReplicationRu](SpatialReplicationRu.md), [Protocol/README](../Protocol/README.ru.md).

### Аккаунты, вход и гостевые соединения

Регистрация и вход — HTTP(S) `/auth/*`: регистрация атомарно создаёт account и profile, вход
выдаёт одноразовый билет, который погашает `OpenSession`; пароль и имена по ENet не идут.
Сохранённый вход: токен (30 дней, до 8 на аккаунт, в SQLite только SHA-256) в Windows
Credential Manager, `ConnectSaved`, выход, «забыть» и пароль по коду из консоли или панели
(форма «Пароль по коду» во вкладке «Аккаунт»). Режим регистрации (`open`, `steam`, `manual`)
меняют панель и консоль на ходу; в ручном режиме игроков создаёт администратор. Вход через Steam
(OpenID в браузере, `[Authentication.Steam]`): аккаунт SteamID входит или создаётся как
`steam.<SteamID>`, если режим разрешает; клиент узнаёт режим и наличие Steam из `GET /auth/methods`
и показывает кнопку «Войти через Steam». Адреса входа
хранятся `SignInHistoryDays` дней и видны в панели; бан диапазона IP закрывает вход, регистрацию и
подключение игры из него; бан аккаунта можно распространить на устройства игрока (хэш UUID платы,
свой для каждого сервера). Без входа клиент держит гостевое соединение (`JoinAsGuest`, без дедлайна): админка
видит запущенные игры, гость занимает место в `Runtime.MaxSessions` наравне с игроком,
забаненная игра остаётся гостем. Удалённый вход по умолчанию требует HTTPS.
[AuthenticationRu](AuthenticationRu.md), [Client.Core](../src/Dreamsleeve.Client.Core/README.ru.md).

### Чат, объявления и API для модов

- Общий (`Global`, ChannelId 1) и системный (`System`, 2) каналы — отдельные `ChatRoomAgent` со
  своей историей в памяти, MessageId и лимитом частоты; в системном только объявления, в общем
  только чат. `SessionOpened.channels` несёт хвост каждого канала, дальше — по одному сообщению.
- Источник объявления назначает сервер (`Server` / `TrustedClient` / `ThirdParty`), вид —
  `Announcement` / `Event` / `Admin` / `Periodic`. У серверных объявлений нет автора (фиктивного
  игрока нет); они приходят из расписания `[[Announcements.Scheduled]]`, консоли и панели.
- Другие моды публикуют через C++ `IVDreamsleeve1` (экспорт `RequestPluginAPI`, как у PrismaUI и
  TrueFlasksNG) и Papyrus `DreamsleeveClient` ([DreamsleeveModApiRu](DreamsleeveModApiRu.md)).
- `Server.ServerName` приходит в приветствии и показывается в заголовках UI.
  [DomainSpecRu §4.8](DomainSpecRu.MD), [ClientUiPlanRu](ClientUiPlanRu.md).

### Онлайн, телеметрия, светлячки, имена и облачка

- `PlayerSession` владеет персонажем, поколением, положением, actor values и деталями (раса,
  уровень, занятие, место, время начала игры). Онлайн и метаданные глобальны; положения
  `PresenceAgent` отдаёт только в радиусе `Runtime.Presence.VisibilityDistance` (8192) внутри
  того же WRLD/CELL, себе — всегда; без своей позиции чужие не видны.
- SKSE-плагин шлёт позу каждые 50 мс, детали и HP/MP/SP (`Resource`) — reliable при изменении
  ([DeathAndActorValuesRu](DeathAndActorValuesRu.md)). Светлячок — временная placed reference
  `FXGlowFillRoundXBrt` на видимого игрока; клиентские `visibilityDistance` и `showFireflies`
  ограничивают отрисовку, но не серверную доставку.
- Имена и облачко последнего сообщения общего канала рисует Scaleform-слой в HUD: один кадр
  надписей на тик для светлячков и меток, стиль и скрытие в бою — в `ui.toml`; в VR отключены.

### Движение

- Клиент шлёт абсолютную позу с context revision и sequence без RequestId и ACK и повторяет
  последнюю по периоду; `SetLocation` (Control) задаёт или очищает контекст. Сервер хранит
  последнее измерение и на каждом `ReplicationIntervalMs` отправляет наблюдателю все видимые
  актуальные позы. Reliable запись видимости в `PresenceChanged` с ViewRevision задаёт baseline или clear;
  realtime сам видимость не создаёт. Кандидатов отбирает индекс по FormKey и трёхмерной сетке.
- `MovementView` игрового потока интерполирует XYZ и углы с задержкой, без экстраполяции;
  история сбрасывается на границах персонажа, пространства и видимости, при телепорте,
  перерыве и снимке. [SpatialReplicationRu](SpatialReplicationRu.md),
  [MovementInterpolationRu](MovementInterpolationRu.md).

### Модерация и имена

- Серверный словарь `moderation.toml` проверяет новые username и display name, тексты
  сообщений, объявлений и меток и имя персонажа. `[block]` отклоняет (`TEXT_NOT_ALLOWED`), имя
  персонажа просто не публикуется; `[flag]` доставляет сообщение с диапазонами
  `ChatMessage.flagged`, клиент показывает, маскирует или скрывает их (`textFilter`).
  Старые профили не переписываются: наружу уходят заместители.
- Антиспам `ChatRoomAgent` по PlayerId: всплеск, пополнение и окно повторов (`[Runtime.Chat.Rate]`).
- Личный игнор (вкладка «Игнор») и локальный режим стримера (псевдонимы из `aliases.toml`) живут
  только в клиенте, в `ui.toml` по адресу сервера; на сервер не передаются.
- Скрытое имя — серверный режим «нет», «везде» или «везде, кроме меток»: остальные видят
  псевдоним из `pseudonyms.toml`. Подмена — в одной точке `PlayerSession`; себе — настоящий
  профиль, настоящие имена — только в админке. Игрок меняет display name из «Аккаунта» с
  интервалом, хранятся 20 последних смен. [ModerationAndNamesRu](ModerationAndNamesRu.md).
- Цвет имени в чате (протокол 20, схема 14): новый аккаунт получает случайный цвет палитры,
  игрок выбирает другой в настройках; сервер не принимает слишком тёмный и меняет не чаще раза в
  10 с. Цвет рисует имя во всех чатах; у псевдонима цвета нет.
  [ModerationAndNamesRu](ModerationAndNamesRu.md#цвет-имени-в-чате).
- Локальные фильтры «только из моих гильдий» для светлячков (с именами и облачками) и для меток
  на земле; свои метки видны всегда. [GuildsRu](GuildsRu.md#в-игре).

### Прокси и маршруты

- Сервер доверяет прокси из `[Proxies] Trusted`: адрес игрока берётся из `X-Forwarded-For`, билет
  помнит адрес входа, и игровое соединение от прокси получает его; сами прокси не банятся, админка
  пишет «через прокси …». Вход через Steam возвращается на адрес прокси (`ProxyUrls`).
- Клиент: основной маршрут и `[[routes]]` в `client.toml`; без ответа — следующий, сработавший
  запоминается, выбор вручную во вкладке «Аккаунт». Сохранённый вход и устройство — по основному.
  [DeploymentRu](DeploymentRu.md) («Прокси»), `Scripts/smoke_proxy.py`.

### Наказания и инструменты модератора

- Мут запрещает писать (чат, надписи, объявления модов через клиент, смену имени; метка
  смерти разрешена), бан закрывает сессию (`SessionEnded`) и отказывает во входе и resume
  (HTTP 403 `banned`), кик закрывает текущую сессию. Срок или бессрочно, причина обязательна,
  наказание истекает само; область пока — весь сервер. После кика и бана SKSE-клиент сам не
  переподключается.
- Роль `Player | Moderator` выдаёт панель, смена доходит до живой сессии (`RoleChanged`).
  Модератор из игры (протокол v15) мутит, банит, кикает, снимает любые наказания, видит их
  список, смотрит и чистит метки игрока, удаляет сообщения; себя и других модераторов наказать
  нельзя. Сессия проверяет роль, `SqliteSanctionStore` — право на цель в той же транзакции, что
  и строка `admin_audit` с `moderator_id`. [Муты, баны и кик](ModerationAndNamesRu.md#муты-баны-и-кик),
  [инструменты модератора](ModerationAndNamesRu.md#инструменты-модератора-в-игре).

### Гильдии

- Протокол 19, схема 13. Глава, офицеры и участники; глава передаёт роль (сам становится
  офицером) и выйти может только после передачи или роспуска. Имя — буквы и цифры, словарь,
  уникально без учёта регистра, без переименования. Лимиты гильдий на сервере, гильдий на игрока
  (свои включая) и участников мягкие и проверяются при действии, приглашение — при принятии.
- Приглашаются игроки онлайн; приглашение ждёт до ответа, истечения (7 дней) или роспуска.
  Участники видят настоящие имена друг друга. Мут в гильдии, удаление сообщений и исключение —
  по рангу выше цели. Новый глава при бане или удалении прежнего и роспуск — из веб-админки.
- Один владелец `GuildsAgent` держит все гильдии в памяти и пишет в SQLite отдельным
  последовательным писателем; чат гильдии хранится в памяти, как общий, и идёт по линии Control
  вместе с изменениями гильдий. Клиент: вкладка на гильдию и «Гильдии» вместе, выбор гильдии
  для отправки, вкладка «Гильдии» в меню с действиями по роли. [GuildsRu](GuildsRu.md).

### Метки на земле

- Надписи (`Note`, до 200 символов, правила чата) и места смерти (`Death`, подпись убийцы или
  причины до 64) — постоянные серверные данные в SQLite. Один владелец `GroundMarksAgent`:
  индекс, видимые наборы наблюдателей с ViewRevision, квоты с вытеснением старейшей метки
  того же автора и вида, срок жизни, плотность ячейки и частота. Видимость — как у поз.
- Метка несёт курс и игровую дату (`GameDate` из `RE::Calendar`, эра всегда 4). Клиент рисует
  плоские glow-статики без коллизии со снапом на пол и подписи с датой; вкладка «Метки»
  показывает полный список своих меток с сервера и метки рядом. [GroundMarksRu](GroundMarksRu.md),
  [SkseClientRu](SkseClientRu.md#метки-на-земле), [DomainSpecRu §4.9](DomainSpecRu.MD).

### Веб-админка

Панель работает в процессе сервера (Falco + htmx, SSR без своего JavaScript), по умолчанию
только на `127.0.0.1:8780`; auth — отдельный хост. Своих правил у неё нет: действия идут к
владельцам через порты. Онлайн с гостями и настоящими именами скрытых игроков, поиск и
карточка игрока, роль, переименование, сброс пароля и отзыв доступа, наказания и кик,
объявления, аудит, токены REST `/api/v1/*` (только чтение), конфигурация только на чтение.
Первичная настройка — одноразовый код в консоли (`admin-setup`, `admin-reset`).
[AdminPanelRu](AdminPanelRu.md); хостинг — там же и в [DeploymentRu](DeploymentRu.md).

### SKSE-клиент

- `Dreamsleeve.Client.dll`: `Runtime` — единственный владелец `ClientApplication`,
  `MovementView`, `Host::Session` и `ui.toml`. Работа с игрой и публичные вызовы Core — на
  главном потоке из хука `Main::Update` (проверен в IDA для SE 1.5.97, AE 1.6.1170, VR); все
  патчи игры собраны в `Hooks.ixx`.
- PrismaUI-host: JSON-bridge с корреляцией requestId, снимок только для Ready-сессии; настройки
  host передаёт странице только событием `settings`, снимок их не несёт. `ui.toml` пишется
  атомарно; SKSE Menu Framework показывает статус и выключатель.
- Enter/F2 активирует чат без паузы, Escape отпускает; при активном чате хук рассылки
  `InputEvent` не отдаёт клавиатуру игре и другим модам ([InputCaptureHookRu](InputCaptureHookRu.md)).
- Сохранённый вход (если есть) выполняется при запуске, после потери соединения — повтор с
  backoff 5→60 с;
  ручное отключение, отказ скрытого имени, кик и бан автоповтор останавливают.
  `python Scripts/package_dist.py` собирает `dist/Client` и `dist/Server`. [SkseClientRu](SkseClientRu.md).

### Клиентский UI

- [Dreamsleeve.Client.UI](../src/Dreamsleeve.Client.UI/README.ru.md): чат с вкладками каналов,
  fade, перетаскиванием, resize и темами; онлайн, профиль, «Аккаунт», «Метки», «Игнор»,
  «Модерация» (только модератору), настройки. До 500 строк на канал, сообщения различаются
  парой «канал + id». Демо-данные стенда (`src/dev`) в игровой бандл не попадают.
- Решения для CPU-рендера Ultralight: перетаскивание и resize пишут в элемент раз в кадр
  анимации (`transform`, `width/height`), store получает итоговую геометрию при отпускании;
  строки истории мемоизированы; выпадающие списки — свой `views/Select.tsx` (нативный
  `<select>` обрезает подписи). Строки ожидания в пассивном чате уходят через 15 с.

### Хранение и логирование

SQLite, схема 9 ([db/README.md](../db/README.md)): аккаунты и профили, пароли, сохранённые
токены, привязки способов входа, метки, администраторы с сессиями и токенами API, роли,
аудит, история имён, наказания. Миграции применяются при старте; более новая или чужая схема
останавливает запуск. HTTP-обработчики и агенты не ждут SQLite: его вызывают ограниченные
workers и последовательный писатель меток. Чат, онлайн, билеты и игровые данные — в памяти.

Сервер пишет Serilog в консоль и JSON-файлы с ротацией. Information описывает регистрации,
входы и отказы, вход в игру и выход, режим скрытия, смену имени, метки, объявления и действия
панели; тексты чата, пароли, билеты и содержимое пакетов не пишутся
([AuthenticationRu](AuthenticationRu.md)). Клиент пишет spdlog.

## Открытые вопросы и ограничения

- **Защита транспорта.** ENet не шифруется: билет защищает вход, но не игровой канал; для
  открытой сети нужна отдельная защита. HTTP без TLS — только loopback или явный opt-in.
  MFA и подтверждения почты нет; привязки Steam к парольному аккаунту нет.
- **Социальный слой.** Друзья, партии, личные сообщения и жалобы не реализованы; для личных
  сообщений фильтр облачков (`Session::Fresh`) нужно расширить явно. Гильдии других игроков,
  кроме общих, клиенту не видны: публичного каталога гильдий и тега гильдии у имени нет.
- **История и сессия.** История чата только в памяти и приходит хвостом при входе, пагинации
  по сети нет. Resume игровой сессии нет; начальный снимок должен уместиться в один пакет.
- **Масштаб.** Настройки по умолчанию рассчитаны на 512 клиентов. Плотная группа в одном
  радиусе остаётся O(N²): при 512 в одном месте такт онлайна сам снижает частоту до ~10 Гц.
  Метаданные и видимость идут одной пачкой на получателя за такт (protocol 16), поэтому 512
  игроков с постоянно меняющимися ресурсами и одновременное появление сотен игроков сервер держит;
  все 512 в одном месте с меняющимися ресурсами — без отключений, но с отставанием в секунды:
  все пакеты кодирует один поток runtime ([замеры 1 октября](benchmarks/load-512-2026-10-01.md)).
  Гистерезиса серверной видимости и шардирования нет.
- **Отказы.** Потеря общей зависимости останавливает runtime, а супервизор перезапускает
  игровую часть целиком по `[Recovery]`: сессии, история чата и онлайн при этом теряются, клиенты
  переподключаются сами ([Server.Core](../src/Dreamsleeve.Server.Core/README.ru.md)). Ошибки
  выделения памяти на границе клиентского владельца не перехватываются; sinks Serilog синхронны.
  `ENet protocol pump failed` с `HostUnreachable` объяснён: ENet бросал весь вызов service из-за
  одной неудачной отправки (смена сети, VPN), теперь такие ошибки проходящие. Не установлен
  виновник падения в аллокаторе Scaleform по Esc с Community Shaders 1.9.1 ([SkseClientRu](SkseClientRu.md)).
- **Админка.** Нет удаления сообщений и меток из панели, правки лимитов и словаря, нескольких
  ролей администраторов и удаления администратора.
- **VR и версии игры.** В VR имена, облачка и подписи меток отключены (нужен стереорендерер).
  Смещения callsite `Main::Update` сняты для SE 1.5.97, AE 1.6.1170 и VR; для других версий AE
  (1.6.640, 1.7.x, GOG/Epic) их нужно снять отдельно. На машине разработки есть только SE 1.5.97.
- **Проверки в игре.** Автоматически проверены сборка DLL, native и managed тесты, UI в
  браузере и smoke с настоящим сервером. По документам остаются ручными в Skyrim и PrismaUI:
  фокус, Enter/Escape и захват клавиатуры (зажатые клавиши, геймпад, конфликтующие моды);
  скрытие при меню, пауза, загрузки, новая игра и главное меню; смерть и воскрешение, actor
  values, торговля и занятия; светлячки (дубли, попадание в сохранение), имена и облачка (два
  клиента, кириллица, окклюзия, fade, скрытие в бою); вид и снап меток, дальности, отправка
  смерти, шапка с датой; скрытое имя и префикс `~`, правый клик и инструменты модератора в
  Ultralight; API модов (получение `IVDreamsleeve1`, callbacks, mod event, кириллица в Papyrus).
