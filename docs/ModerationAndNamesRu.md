# Модерация, игнор и отображаемые имена

Реализовано 29 сентября 2026 года; скрытое имя, муты, баны и кик — 30 сентября, инструменты
модератора в игре — 1 октября 2026 года. Документ описывает словарь сервера, антиспам, личный чёрный список, выбор
отображаемого имени, локальный режим стримера, серверное скрытое имя, наказания и инструменты
модератора. Жалоб, внешних API и ML нет; админка — [AdminPanelRu.md](AdminPanelRu.md).

## Серверный словарь

Файлы:

| Файл | Назначение |
|---|---|
| `src/Dreamsleeve.Server/moderation.example.toml` | Поставляемый словарь стрим-безопасности и описание формата |
| `moderation.toml` рядом с сервером | Рабочий словарь; путь — `[Moderation] RulesPath` |
| `server.example.toml`, секция `[Moderation]` | `Enabled = true` (по умолчанию), `RulesPath` |

`dist/Server` получает `moderation.example.toml` и, если его ещё нет, `moderation.toml`
с тем же содержимым. Файл читается только при запуске. Отсутствующий файл —
предупреждение в логе и пустой словарь; синтаксическая ошибка, неизвестный ключ
или не-строки в списках останавливают запуск. `Enabled = false` отключает только
словарь, антиспам остаётся.

Два уровня:

```toml
[block]                             # отказ: имена при регистрации, сообщения, имя персонажа
words = ["kill yourself"]           # целое слово или фраза
substrings = ["childporn"]          # в любом месте, в том числе внутри слова
exceptions = []                     # разрешённые слова/фразы

[flag]                              # сообщение доставляется, диапазоны помечаются
words = ["sieg heil", "t.me"]
substrings = ["nigga"]
exceptions = ["niggardly"]
```

Ключи `words`/`substrings`/`exceptions` на верхнем уровне (формат первой версии)
читаются как `[block]`. У каждого уровня свои исключения. Флаги применяются к тексту
сообщений, объявлений и надписей; имена проверяются уровнем `[block]` (для чужих имён есть
режим стримера).

Поставляемый словарь нацелен не на мат (он разрешён на крупных стриминговых
площадках), а на то, что опасно показывать в эфире. `[block]` узкий: сексуальный
контент с несовершеннолетними, прямые призывы к самоубийству, сватинг. `[flag]` —
этнические и гомофобные оскорбления (EN/RU), нацистские лозунги и символика,
террористические и запрещённые организации, угрозы, темы самоповреждения,
сексуальный контент и предложения, торговля наркотиками, реклама казино и
скам-раздачи, приглашения/сокращатели/IP-логгеры, запросы личных данных. Политические
взгляды, религия, ориентация и гендерная идентичность как темы и имена публичных
людей намеренно не включены: законы разных стран различаются, такие записи
администратор добавляет сам. Ложные срабатывания проверены тестом на корпусе
обычных игровых фраз («хачапури», «жидкость», «Нигер», «упорно», «chink in the armor»).

Правила:

- `words` требуют границы слова с обеих сторон (соседний символ не буква и не цифра).
  Пробелы во фразе совпадают с любым количеством пробелов и знаков между словами.
- Поиск подстроки включается только явным правилом в `substrings`.
- Исключение — целое слово или фраза. Совпадение правила, целиком лежащее внутри
  найденного исключения, игнорируется; другие совпадения в том же тексте — нет.

Сравнение идёт по отдельному нормализованному представлению; исходный текст
сохраняется и рассылается без изменений. Нормализация (`Moderation.normalize`):
NFKC (полноширинные и «математические» буквы), инвариантный нижний регистр,
удаление диакритики и других комбинируемых знаков, форматирующих и невидимых
символов (ZWSP/ZWJ, soft hyphen, bidi, Hangul filler), схлопывание пробелов,
сведение похожих кириллических/греческих букв к латинским. Шаблон правила
дополнительно принимает цифры и символы вместо букв (`4 @`→a, `3`→e, `1 ! |`→i,
`0`→o, `5 $`→s, `7`→t, `8`→b), растянутые буквы (`baaad`, но не меньше повторов,
чем в правиле: `as` не совпадает с `ass`) и знаки внутри слова (`b.a.d`, `b_a_d`).
Знаки внутри самого правила необязательны: `t.me` совпадает и с `tme`, `14/88` — с `1488`.
Буквы, разделённые пробелами (`b a d`), не склеиваются — иначе ложные срабатывания
на обычных фразах. Нормальные международные имена не меняются и не отвергаются,
если в них нет слов из словаря. Сопоставление линейно: соседние классы символов
не пересекаются, используются атомарные группы.

Где проверяется:

| Данные | Когда | Результат |
|---|---|---|
| Username | регистрация (`/auth/register`) | HTTP 400 `username_not_allowed`; префикс `hidden.` и имена `server`, `system` зарезервированы |
| Display name | регистрация | HTTP 400 `display_name_not_allowed` |
| Текст сообщения, `[block]` | `PlayerSession` до передачи в канал | `ChatRejected`, код `TEXT_NOT_ALLOWED`; не сохраняется и не рассылается |
| Текст сообщения, `[flag]` | `PlayerSession`, вне владельца канала | сообщение принимается; `ChatMessage.flagged` — диапазоны в байтах UTF-8, хранятся с сообщением и выдаются в истории |
| Имя персонажа | `BeginCharacter`/`RenameCharacter` до публикации | имя не публикуется: `character_name` отсутствует, `character_name_withheld = true` |
| Текст объявления клиента, `[block]` / `[flag]` | `PlayerSession` до канала | как у сообщения: `TEXT_NOT_ALLOWED` (поле `text`) / диапазоны `flagged` |
| Подпись объявления (`source` мода), `[block]` | `PlayerSession` до канала | `TEXT_NOT_ALLOWED`, поле `source` |

Смена display name после регистрации (игроком из игры или администратором в панели) проходит
ту же проверку, см. «Смена отображаемого имени» ниже. Вход (`/auth/login`) имена не проверяет.

Имя персонажа приходит из игры и в сохранении Skyrim не меняется. Сессия хранит
его для игровой логики, но все исходящие проекции (присутствие, bootstrap, снимок
в сообщениях чата, ответ `Read`) проходят через одну функцию `publicSnapshot`.
Клиент показывает вместо скрытого имени проверенный display name.

### Старые аккаунты и история

Учётные записи в SQLite не перезаписываются. При открытии сессии профиль проходит
`Moderation.publicProfile`: если сохранённый username или display name не проходит
текущие правила, наружу уходит заместитель `hidden.<id>` / `Player <id>`. Все пути
выдачи (профиль автора в сообщении, онлайн, приветствие, уведомления) берут профиль
из сессии, поэтому запрещённое имя не утекает через вложенный профиль. Владелец
аккаунта по-прежнему входит своим username.

История чата хранится только в памяти сервера и теряется при перезапуске, а
правила читаются только при запуске. Поэтому сообщения прошлых запусков с
другими правилами никогда не выдаются, а новые правила действуют на всю текущую
историю; разрушительная перезапись истории не нужна.

## Антиспам

Существующие лимиты: максимальная длина `Server.ChatInput.MessageText` (2000 скаляров
Unicode, проверяется codec; клиент получает `INVALID_REQUEST`, поле `text`,
«Message exceeds N characters.»), очередь `Runtime.Player.MaxPendingChat`.
Настройки в `[Runtime.Chat.Rate]` (те же три ключа ограничивают объявления клиентов
`[Announcements.Rate]` и надписи `[GroundMarks.NoteRate]`):

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `Burst` | 5 | Сколько сообщений можно отправить подряд |
| `RefillMs` | 2000 | Одно новое сообщение каждые N мс, до `Burst` |
| `DuplicateWindowMs` | 30000 | Тот же нормализованный текст отклоняется в этом окне; 0 отключает |

Состояние ведёт `ChatRoomAgent` по стабильному `PlayerId`, а не по соединению:
переподключение не сбрасывает лимиты. Для каждого автора хранятся токены и не
более 8 последних отпечатков; записи без активности дольше
`max(Burst × RefillMs, DuplicateWindowMs)` удаляются. Отклонённая попытка
не тратит токен, отклонённое сообщение не сохраняется и не рассылается; автор
получает `RATE_LIMITED` в ответ на свой `request_id`.

## Отказ в UI

Оптимистическая строка UI уже коррелирует `requestId` → Core `RequestId` → ответ.
Host переводит известные коды в текст: `TEXT_NOT_ALLOWED` — «Сообщение содержит
запрещённые слова», `RATE_LIMITED` — «Слишком часто или повтор того же сообщения»,
длина — «Сообщение слишком длинное»; неизвестные коды показывают текст сервера.
Строка переходит в «Не отправлено: причина» с ручным повтором.

## Помеченные сообщения на клиенте

Настройка «Помеченные сообщения» (`ui.toml`: `textFilter`, по умолчанию `off`):

- `off` — показывать как есть;
- `mask` — каждый символ помеченного диапазона заменяется `*`, пробелы сохраняются;
- `hide` — чужое сообщение не показывается вовсе, собственное — заглушкой
  «[скрыто фильтром]», чтобы его отправка была видна завершённой.

Фильтр применяет host (`Bridge::ShownText`) до передачи в UI и в облачка: исходный
текст помеченного сообщения при включённом фильтре не пересекает bridge и не
появляется над светлячком. Строки с применённым фильтром помечаются `filtered` и
показываются приглушённо. Смена режима применяется сразу вместе с именами командой
`displaySettings` и повторной проекцией истории; видимые облачка сбрасываются.
Codec клиента принимает диапазоны только внутри текста, по возрастанию, без
перекрытий и на границах символов UTF-8, иначе сообщение отвергается как некорректное.

## Личный чёрный список

«Игнорировать» — в контекстном меню ника в чате (правый клик: «Открыть профиль»,
«Игнорировать»/«Не игнорировать»; для себя — только профиль) или в профиле игрока,
в том числе для автора истории, который уже не в сети. Меню закрывается Escape
(окно чата остаётся активным) или кликом вне него; в Ultralight меню открывается и
по нажатию правой кнопки, если событие `contextmenu` не приходит. Список — отдельная вкладка
«Игнор» меню Dreamsleeve: имя (по текущим настройкам имён), в сети ли игрок, «Профиль» и
«Не игнорировать». Хранение — `ui.toml`, `[[names.ignored]]`,
по ID аккаунта и адресу сервера `ip:port` из `client.toml`: ID уникален только внутри
сервера, записи разных серверов не пересекаются. На сервер список не передаётся.

Игнор скрывает сообщения игрока в чате, включая уже загруженную историю, и облачка
над светлячком: видимое облачко удаляется сразу. Объявления, отправленные клиентом
игнорируемого игрока (его модами), скрываются тоже; серверные объявления — нет. Его метки на
земле не рисуются и не попадают в список меток рядом. Сам светлячок, надпись и
присутствие в онлайне остаются. Свои сообщения и серверные объявления (у них нет автора)
под игнор не попадают, себя проигнорировать нельзя. После снятия игнора история
снова видна в чате, но облачка не всплывают: порог облачков двигается и по
скрытым сообщениям, а повторная проекция приходит как refresh-снимок без облачков.

## Выбор отображаемого имени

Настройка «Отображение имён» (`ui.toml`: `nameMode`, `streamerMode`):

- `username` — имя пользователя;
- `display` — отображаемое имя (по умолчанию);
- `character` — имя персонажа; без него — проверенный display name, затем «Путник».
  В сообщениях используется снимок имени персонажа на момент отправки
  (`ChatMessage.character_name`); текущий персонаж игрока в старые сообщения не
  подставляется, сообщения без снимка показывают display name.

Старое значение `account` читается как `username`. Профиль со скрытым именем
(`pseudonymous`, см. «Скрытое имя») называется серверным псевдонимом при любом режиме:
username пуст, персонажа нет, заместитель «Путник» не подставляется; локальный режим
стримера у наблюдателя по-прежнему ставит свой алиас. Разрешение имени одно:
`Host::Names::NameFor` в SKSE-host. Оно заполняет поле `name` каждого игрока и автора
для UI и надписи над светлячками, поэтому чат, онлайн, профиль, список игнора,
надписи и облачка не расходятся. Облачко содержит только текст; имя над ним —
та же надпись. Смена режима применяется сразу: UI отправляет `displaySettings`, host
сохраняет `ui.toml` и повторно проецирует снимок (`refresh`), нативные надписи
пересчитываются в следующем кадре.

## Режим стримера

В блоке настроек «Режим стримера» два независимых переключателя: «Скрывать чужие имена
(только у меня)» — этот раздел, ключ `streamerMode`, — и «Скрывать моё имя от других
игроков» — раздел «Скрытое имя» ниже, ключ `hideIdentity` (`off` / `everywhere` /
`exceptGroundMarks`).

Псевдонимы берутся из клиентского словаря `SKSE/Plugins/Dreamsleeve/aliases.toml`
(`src/Dreamsleeve.Client/aliases.toml`, 24 имени в духе Skyrim). Пустой, слишком
большой, повреждённый или отсутствующий файл заменяется встроенным списком;
недопустимые записи пропускаются. Каждому аккаунту при первой встрече выбирается
случайное имя из словаря (не из настоящего имени), совпадения получают короткий
номер («Страж 2»). Назначение хранится в `ui.toml`, `[[names.aliases]]`, по адресу
сервера и ID; записи пишутся пачкой не чаще раза в 5 секунд, максимум 4096 (старые
вытесняются). Сервер псевдонимы не назначает и не получает.

В режиме стримера host не передаёт в UI настоящие username, display name и имя
персонажа: `displayName` и `alias` содержат псевдоним, `username` пуст, `character`
отсутствует. Это касается чата, онлайна, карточек, профиля, подсказок, поиска
(ищет только по псевдониму и месту), списка игнора, нативных надписей, сохранённого
логина в панели «Аккаунт» и странице SKSE Menu Framework. Между включением режима
в UI и приходом повторной проекции UI показывает заместитель «Псевдоним…», а не
настоящее имя (прежде это был текст «Скрытое имя»; он переименован, чтобы не путать
заместитель с серверным режимом). Системные тексты host не содержат имён игроков.

Режим стримера не гарантирует безопасность пользовательского текста: имена,
написанные внутри сообщений, не заменяются; содержимое защищает только серверный
словарь. Названия мест, NPC и занятий не скрываются. Лог клиента и файлы
`ui.toml` содержат настоящие данные.

## Скрытое имя

Серверный режим: игрок включает «Скрывать моё имя от других игроков», и все остальные
видят вместо его имени пользователя, отображаемого имени и имени персонажа псевдоним из
серверного словаря. Доменная модель — «публичная личность»
([DomainSpecRu.MD §3.1](DomainSpecRu.MD)): профиль после заместителей модерации либо
псевдоним; PlayerId открыт всегда.

Режим выбирается одним из трёх вариантов: «Нет», «Везде, включая метки на земле» и
«Везде, кроме меток на земле». Онлайн, надпись над светлячком и чат (сообщения и объявления
клиента) всегда скрываются вместе — это проекции, которые сервер отправляет одним путём;
отдельно выбираются только метки на земле. В домене это `HiddenIdentity = Shown | Everywhere | ExceptGroundMarks`,
в протоколе — enum `HiddenIdentity` (`NONE`, `EVERYWHERE`, `EXCEPT_GROUND_MARKS`). При варианте
«кроме меток» новые метки несут настоящий профиль и имя персонажа, как без режима; по
PlayerId метки такую связь с псевдонимом раскрывают — об этом предупреждает текст под
выбором.

Файлы и настройки:

| Файл / ключ | Назначение |
|---|---|
| `src/Dreamsleeve.Server/pseudonyms.example.toml` | Поставляемый словарь: 24 имени клиентского `aliases.toml`, формат и правила |
| `pseudonyms.toml` рядом с сервером | Рабочий словарь; путь — `[Identity] PseudonymsPath` |
| `[Identity] AllowHiddenIdentity` | `true` по умолчанию; `false` запрещает режим (`HIDDEN_IDENTITY_NOT_ALLOWED`) |
| `[Identity] ToggleIntervalMs` | 30000: переключение не чаще одного раза за интервал в сессии (`RATE_LIMITED`); 0 снимает лимит |
| `ui.toml`, `[ui] hideIdentity` | Выбор игрока: `off`, `everywhere`, `exceptGroundMarks`; host отправляет его при открытии сессии |

Словарь читается при запуске, как `moderation.toml`, но никогда не останавливает сервер:
отсутствующий, больше 64 КиБ, повреждённый или пустой файл заменяется встроенным
списком (те же 24 имени) с предупреждением в логе; записи, нарушающие правила (1–48
байт UTF-8, без пробелов по краям, управляющих символов и `< >`), и повторы пропускаются,
их число пишется в лог. Используется не больше 1024 имён. `dist/Server` получает
`pseudonyms.example.toml` и, если его ещё нет, `pseudonyms.toml`.

Выбор псевдонима (`PseudonymBook`, владелец — `SessionTable` в runtime, рядом с резервом
PlayerId): случайное имя из словаря, никогда не из настоящих имён. Имя, уже видимое онлайн
(username и display name показанных игроков, псевдонимы скрытых; сравнение без регистра
после NFC), включая собственные настоящие имена игрока, получает наименьший свободный
номер: «Страж 2»; настоящие имена игрока со скрытым «кроме меток» именем тоже считаются
видимыми (они остаются на его метках). Новый псевдоним — при каждом открытии сессии со
скрытым именем и при каждом включении режима из «Нет»; смена «везде» ↔ «кроме меток»
оставляет прежний. Псевдоним освобождается вместе с резервом PlayerId и между сессиями не
хранится. Повторный запрос текущего варианта не считается переключением; любая другая смена
подчиняется `ToggleIntervalMs`.

Точка подмены одна — `PlayerSession.publicSnapshot`/`publicIdentity` (рядом с
`Moderation.publicProfile`): всё, что уходит от сессии к другим владельцам, уже содержит
псевдоним — снимок и обновления присутствия (bootstrap `SessionOpened.players`,
`PresenceChanged.joined`/`updated`), автор в `ChatSubmission` (сообщения чата и объявления
клиента), псевдоним в `GroundMarkSubmission` (надписи и места смерти; только при варианте
«везде» — `markPseudonym`/`markCharacterName`). Настоящие имена
скрытого игрока к другим сессиям не попадают даже в памяти. Сам игрок получает свой
настоящий профиль: сессия восстанавливает свою запись в приветствии и в
`PresenceChanged.updated`, а текущий псевдоним приходит в `SessionOpened.own_pseudonym` и в ответе на
переключение. Смена разъезжается существующим путём личности в `PresenceAgent`
(`identityEqual` сравнивает публичную личность целиком, конфликт определяется по PlayerId).

История. Снимок автора сообщения фиксируется при отправке: сообщения, объявления и метки,
созданные при скрытом имени, навсегда остаются с псевдонимом; созданные до включения — с
настоящим профилем. Метка хранит псевдоним в SQLite (`ground_marks.author_pseudonym`,
миграция 4), поэтому и после перезапуска сервера она не раскрывает автора, даже если он
уже показывает настоящее имя. Метка без псевдонима, как и раньше, показывает текущий
профиль автора. Свои сообщения, отправленные при скрытом имени, автор видит под
псевдонимом — как их видят остальные.

Клиент. `hideIdentity` в `ui.toml` пишет только host: при открытии сессии он уходит в
`OpenSession.hidden_identity`, чтобы настоящий профиль не попал в первый `PresenceChanged.joined`; в
сессии UI отправляет `setIdentityVisibility{hiding}`, host — `SetIdentityVisibility{hidden}` с
RequestId, и выбор сохраняется, только когда сервер подтвердил. Без сессии меняется только
выбор для следующего входа; пока сессия открывается, переключатель отвечает «Дождитесь
подключения к серверу». UI показывает «Ожидание сервера…», пока ответа нет, затем «Другие
видят вас как „Страж 2“» (при «кроме меток» — с добавкой «в метках на земле — ваше имя») — в
настройках и в панели «Аккаунт». Отказ возвращает
переключатель и показывает причину: «Слишком часто…» или «Сервер не разрешает скрывать имя».
Если сервер отказал при открытии сессии, автоматические переподключения останавливаются
(иначе каждое получало бы тот же отказ); игрок выключает режим и входит снова.

Пометка. В чате, онлайне и профиле псевдонимный игрок помечается знаком `~` перед именем
(`data-pseudonymous` на строке или имени, подсказка «Имя скрыто игроком»), в
контекстном меню автора — строка «имя скрыто игроком», в профиле вместо имени
персонажа — «Имя скрыто игроком». Надписи над светлячками и метками на земле получают
тот же префикс: `~Страж 2` (`Host::Names::PlateName`). Игнор, локальные алиасы и
карточка работают по PlayerId без изменений.

Ограничения. PlayerId стабилен и публичен: наблюдатель может сопоставить псевдонимы одного
игрока между сессиями. Имена внутри текста сообщений не заменяются; раса, уровень, место и
занятие не скрываются. Лог и база сервера хранят настоящую личность (это норма: администратор
знает аккаунт); псевдонимы и тексты — обычный UTF-8, никогда не HTML/JS.

Админка. Веб-панель сервера — серверная поверхность, а не игрок, поэтому правило «настоящие
имена скрытого игрока не покидают сервер» на неё не распространяется: в таблице онлайна и в
карточке игрока она показывает настоящие username, display name и имя персонажа вместе с
текущим псевдонимом и вариантом режима (знак `~` перед псевдонимом — тот же, что у игроков).
Инвариант остаётся прежним: ни один пакет игрового протокола другому игроку не содержит
настоящих имён; данные панели доступны только после входа администратора, никогда не
попадают в игровые сессии и не проходят через игровой протокол, а её REST-ответы подчиняются
той же аутентификации, что и страницы. Строки аудита панели фиксируют настоящую личность.
Панель хранит псевдонимные проекции сообщений и меток как есть: она не «раскрывает» историю,
она видит то же, что лог сервера.

## Смена отображаемого имени

Игрок меняет своё отображаемое имя сам (панель «Аккаунт» в UI, `name <имя>` в Client.Dev);
username и PlayerId остаются. Протокол v11: `ChangeDisplayName` → `DisplayNameChanged`
([Protocol/README.ru.md](../Protocol/README.ru.md#смена-отображаемого-имени)).

- Проверки: правила `DisplayName` (кодек сервера, лимит `[Server.ChatInput] DisplayName`),
  словарь `[block]` (`PlayerSession`, как у регистрации — `TEXT_NOT_ALLOWED`),
  `[Identity] AllowDisplayNameChange` (`DISPLAY_NAME_CHANGE_NOT_ALLOWED`), одна смена за раз,
  интервал `[Identity] DisplayNameChangeIntervalMinutes` (по умолчанию 1 минута; 0 — без лимита).
- Интервал считает `AuthService` по таблице `display_name_changes` (SQLite, миграция 6) в одной
  транзакции с заменой имени, поэтому переподключение и перезапуск его не сбрасывают. Смены
  администратором в интервал не входят и не ограничиваются.
- Путь: `PlayerSession` → `AuthService` (`DisplayNameChangeRequest`, workers `account-storage`) →
  ответ сессии → тот же путь, что у переименования из панели: `Moderation.publicProfile`,
  `SessionHostCommand.UpdateProfile` (книга имён), `PresenceCommand.Update` и
  `GroundMarkCommand.Rename`. Остальные получают обновлённого игрока в `PresenceChanged` (`identityEqual`); новые
  сообщения и метки несут новое имя, старые сообщения сохраняют снимок автора.
- Скрытое имя: пока игрок скрывает имена, другие видят псевдоним и его обновлений не получают;
  настоящее новое имя не уходит ни в один пакет другому игроку (проверено побайтно).
- Невыкупленные билеты игрока получают новое имя сразу; история смен — `display_name_changes`
  (старое, новое, кто: игрок или администратор, когда) — видна в карточке игрока админки.
  Хранятся последние `[Authentication.Service] DisplayNameHistory` (20) смен игрока, более старые
  удаляются при записи новой, как квоты меток на земле.
- Лог: `Player {PlayerId} {Username} changed display name: {Previous} -> {DisplayName}` и отказ по
  интервалу; смена администратором пишется в лог и в `admin_audit`.

## Муты, баны и кик

Модель — `Sanctions.fs` домена сервера, хранение — таблица `sanctions` (время в миллисекундах).

- **Мут** запрещает писать: общий чат, надписи на земле, объявления модов через клиент игрока
  и смену отображаемого имени. Метка смерти разрешена: её текст пишет игра. Читать можно всё.
  Отказ — `REQUEST_REJECTION_CODE_MUTED`; клиент закрывает поле ввода и показывает причину и срок.
- **Бан** закрывает живую сессию (уведомление `SessionEnded`, затем разрыв) и отказывает во
  входе и resume: HTTP 403 `banned` с `reason` и `untilUnixMs` (403, не 401: сохранённый вход
  не удаляется и снова работает после бана). Билеты, выданные до бана, гаснут. Игра забаненного
  остаётся на сервере гостем.
- **Бан с устройствами**: галочка в диалоге бана и в панели распространяет бан на устройства игрока
  ([AuthenticationRu.md](AuthenticationRu.md#устройства)): с них не войти и не зарегистрироваться,
  пока бан действует.
- **Бан диапазона IP** (только панель, [AuthenticationRu.md](AuthenticationRu.md#адреса-входа-и-баны-ip))
  закрывает вход, регистрацию и подключение игры из диапазона; открытые оттуда сессии получают
  `SessionEnded` с причиной `ADDRESS_BANNED`.
- **Кик** закрывает текущую сессию с причиной; войти снова можно сразу, но SKSE-клиент после
  кика и бана сам не переподключается — игрок входит вручную.
- **Срок**: от минуты до десяти лет или бессрочно («таймаут» — это мут со сроком). Наказание
  истекает само: действие сверяется со сроком в момент проверки, без таймеров. Причина
  обязательна: одна строка до 200 символов, её видит игрок и хранит аудит.
- **Кто**: панель может всё; модератор — только игроков (`PlayerRole.outranks`), не себя и не
  другого модератора. Модераторы равны: любой снимает наказание, выданное другим. Наказание
  одного вида у игрока одно: новое заменяет действующее. Остальным игрокам ничего не сообщается.
- **Область**: сейчас весь сервер (`SanctionScope.Server`); гильдейские муты станут отдельной
  областью с тем же правилом «роль выше цели».

Живые сессии следуют изменениям без переподключения: `AuthService` пишет строку и сообщает
runtime `AccountChange` (`Banned`, `MuteChanged`), runtime хранит муты с момента старта
(`SessionTable.Mutes`, как роли) и передаёт их сессии после резерва PlayerId. Мут в
`SessionOpened.mute`; если он пришёл, пока сессия открывалась, клиент получает `MuteChanged`
сразу после приветствия.

## Инструменты модератора в игре

Модератор — роль аккаунта, её выдаёт и забирает панель. Клиент узнаёт роль из
`SessionOpened.role`, смену в живой сессии — из `RoleChanged`; инструменты UI видны только
модератору, но решает сервер: каждую просьбу сессия проверяет по роли (`NOT_PERMITTED`), а кого
можно наказать — `SqliteSanctionStore` по сохранённым ролям (`PlayerRole.outranks`). Скрытого
игрока модератор видит по псевдониму и действует на него по публичному PlayerId; настоящие имена
есть только в панели.

Где в UI:

- Контекстное меню ника в чате (правый клик): «Удалить сообщение» (то, на котором открыто меню),
  а для чужого ника — «Мут…», «Бан…», «Кик…», «Метки игрока», «Удалить все надписи…» и
  «Удалить все места смерти…». Те же действия — кнопками в профиле игрока.
- Вкладка «Модерация» (только модератору): действующие наказания, в том числе офлайн-игроков, с
  кнопкой «Снять»; игрок, которого клиент не встречал (не в сети и не автор истории), показан
  номером `#PlayerId`. Ниже — все метки игрока, которого модератор запросил, с удалением по одной и
  «Удалить метки…».
- Диалог мута и бана: срок (15 минут, 1 час, 1 день, 7 дней, 30 дней, бессрочно или другой срок в
  минутах, часах или днях), обязательная короткая причина и две галочки, по умолчанию выключенные:
  заодно удалить все надписи и/или все места смерти игрока (отдельный запрос). Кик — только
  причина; удаление меток — выбор видов. Диалог ждёт ответа сервера; отказ (например, цель —
  модератор) показывается в нём же, успех — строкой статуса.

Кто владеет чем:

- Мут, бан, кик и список наказаний — `AuthService` (`ModerationCommand` → `AccountAccessCommand`):
  `SqliteSanctionStore` проверяет право и пишет строку аудита в той же транзакции, затем
  `AccountChange` (`Banned`, `MuteChanged`, `Kicked`) доходит до runtime и живой сессии. Кик
  панели идёт тем же путём.
- Сообщения и метки — их агенты: `ChatRoomAgent` (`Remove`: `Chat.remove` убирает сообщение из
  истории без пропуска — читать нечего, ID повторно не принимается; всем участникам —
  `ChatMessageRemoved`), `GroundMarksAgent` (`Remove` с «любым автором» для модератора, `ListOf`,
  `ClearOf` по видам; одна процедура `drop` для удаления, чистки и истечения). Сессия получает
  ответ владельца с автором и отправляет строку аудита (`ModerationCommand.Record`) в
  `AuthService`; удаление своей метки модератором аудита не пишет.
- Аудит — `admin_audit` с `admin_id` или `moderator_id` (схема 9): `sanction_player`,
  `lift_sanction`, `kick_player`, `delete_chat_message` (текст сообщения), `remove_ground_mark`,
  `clear_ground_marks` (число). Панель показывает «Кто»: администратор, модератор или «удалённый
  модератор», если профиля уже нет.

Клиент: Core различает вытеснение из кэша (`ChatMessagesEvicted`, UI держит свою историю
длиннее кэша) и удаление модератором (`ChatMessagesDeleted`: сообщение уходит и из кэша, и из
истории UI, даже если кэш его уже вытеснил); удаление, пришедшее по Chat-полосе раньше
приветствия, ждёт его, как сообщения. Host шлёт странице `messagesRemoved` и убирает облачко этого
сообщения над светлячком. Ответы модератору — `moderationResult`; имена в списке наказаний host
подставляет для игроков онлайн и авторов истории.

Дальше: гильд-мастера и офицеры смогут удалять сообщения и мутить в чате своей гильдии — та же
цепочка с областью наказания гильдии и правилом «роль выше цели».

## Протокол

Protocol **v15** — инструменты модератора, подробно в
[Protocol/README.ru.md](../Protocol/README.ru.md#модерация): роль в приветствии и `RoleChanged`,
запросы `SanctionPlayer`, `LiftSanction`, `KickPlayer`, `ListSanctions`, `ListPlayerMarks`,
`ClearPlayerMarks`, `DeleteChatMessage` (Chat-полоса) и их ответы, коды `NOT_PERMITTED = 17` и
`TARGET_NOT_FOUND = 18`.

Protocol **v14**: `SessionOpened.mute = 11` (`MuteState{reason, optional until_unix_ms}`),
`ServerPacket.mute_changed = 27` (`MuteChanged{mute}`, без mute — снят),
`ServerPacket.session_ended = 28` (`SessionEnded{reason, text, optional until_unix_ms}`, причины
`ACCESS_REVOKED`, `BANNED`, `KICKED`; последний пакет перед закрытием), код
`REQUEST_REJECTION_CODE_MUTED = 16`.

Protocol **v10** (скрытое имя; несовместим с v9, клиент и сервер обновляются вместе):
`PlayerProfile.pseudonymous = 4` (при нём `username` пуст, `display_name` — псевдоним,
имени персонажа нет; клиент отвергает профиль с username или пустым именем), enum
`HiddenIdentity` (`NONE = 0`, `EVERYWHERE = 1`, `EXCEPT_GROUND_MARKS = 2`),
`OpenSession.hidden_identity = 4`, `SessionOpened.own_pseudonym = 9` (optional) и
`SessionOpened.hidden_identity = 10`, `ClientPacket.set_identity_visibility = 17`
(`SetIdentityVisibility{hidden}`, Control), `ServerPacket.identity_visibility_changed = 25`
(`IdentityVisibilityChanged{optional pseudonym, hidden}`, RequestId обязателен; псевдоним есть
ровно тогда, когда вариант не `NONE`), код `REQUEST_REJECTION_CODE_HIDDEN_IDENTITY_NOT_ALLOWED = 14`.

Словарь и снимок имени добавлены в protocol v6: `ChatMessage.character_name = 6` (optional),
`PlayerInfo.character_name_withheld = 9`, коды `REQUEST_REJECTION_CODE_TEXT_NOT_ALLOWED = 9`
и `REQUEST_REJECTION_CODE_RATE_LIMITED = 10`, `ChatMessage.flagged = 7` (`TextSpan`:
`start`, `length` в байтах UTF-8). Версия протокола проверяется строго: пакеты другой
версии отвергаются, совместимых fallback нет.

## Проверки

- Managed: нормализация, границы слов, подстроки и исключения, международные имена,
  заместители профилей; отказ текста до канала, скрытие профиля и имени персонажа в
  сессии; burst по аккаунту после переподключения, повтор нормализованного текста,
  восполнение; регистрация с запрещёнными/зарезервированными именами; TOML словаря
  и пример; codec снимка имени и длины; уровень `[flag]`: байтовые диапазоны исходного
  текста (невидимые и комбинируемые символы внутри), слияние, исключения, доставка с
  сообщением и в истории; секции `[block]`/`[flag]`; корпус ложных срабатываний.
- Native: codec снимка/флага; разрешение имени и fallback; стабильность, номера,
  сохранение и разделение псевдонимов по серверам; словарь с повреждённым файлом;
  игнор (себя/системные, серверы, перезапуск); фильтр истории, дельт и облачков,
  refresh без повторных облачков; отсутствие настоящих имён в событиях режима
  стримера и совпадение имени надписи с UI; тексты отказов; валидация диапазонов
  в codec, маскирование UTF-8, режимы `mask`/`hide` в истории, дельтах и облачках.
- UI: vitest (неотправленное сообщение с причиной, refresh-снимок, имена, парсер,
  контекстное меню, фильтр) и Playwright в Edge (режим стримера без настоящих имён,
  игнор и его снятие, правый клик по нику, звёздочки и скрытие).
- `Scripts/smoke_chat.py`: реальный сервер и два Client.Dev — словарь (`9`) и повтор
  (`10`) отклоняются, до собеседника текст не доходит.
- Смена отображаемого имени. Managed: кодек (Trim + NFC, лимит, отказ с полем, корреляция),
  сессия (словарь до сервиса, текущее имя сразу, одна смена за раз, запрет конфигурацией,
  интервал с минутами в тексте, обновление presence, книги имён и меток), runtime (новое имя у
  других; у скрытого игрока — ни одного пакета с ним), `AuthService` и SQLite (интервал только
  для собственных смен, история, одно и то же имя не пишется). Native: кодек, `ClientRuntime`
  (подтверждение, Busy, пустое имя не уходит, отказ без сбоя сессии), host (ожидание, итог один
  раз, тексты отказов, обрыв соединения). UI: vitest и Playwright (панель «Аккаунт»).
  `smoke_chat.py`: `name` в Client.Dev — подтверждение и новое имя у собеседника, отказ по
  словарю и по интервалу.
- Скрытое имя. Managed: примитив и словарь (правила, повторы, встроенный список = клиентский
  `aliases.toml`), книга псевдонимов (выбор по индексу, не из имени, номера при совпадении с
  именами онлайн и своими, освобождение), публичная личность в снимке/сообщении/метке;
  сессия (подмена во всех проекциях, себе — нет, переключение, лимит, идемпотентность,
  запрет конфигурацией, вариант «кроме меток»); runtime (байтовая проверка: ни один пакет другому игроку не
